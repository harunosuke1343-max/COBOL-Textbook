第一章
COBOLの概説
1、COBOLの単位

語はCOBOL予約語、あるいはプログラマーによって定義される語のいずれかである。

予約語はCOBOLコンパイラーに対し、特定の統語上意味を持っている。

プログラマーによって定義される語は、データ名やプログラム名などの項目で名前を付ける際はCOBOLの規則に従わなければならない。

2、4つのDIVISION

各DIVISIONは、論理的な順序に配置される。DIVISIONのコーディングの順序は下記のとおりである。

IDENTIFICATIONDIVISION.（見出し部）
ENVIRONMENTDIVISION.（環境部）
DATADIVISION.（データ部）
PROCEDUREDIVISION.（手続き部）
  • IDENTIFICATION DIVISION では、プログラム名、プログラム作成者、作成日などを記入する。
  • ENVIRONMENT DIVISION では、プログラムを処理する具体的な計算機の構成に関する情報、JCLのDD名とDCB名の対応づけなどを記入する。
  • DATA DIVISION では、プログラムで扱う全てのデータの形式、性質、及び作業用エリアとして使用するエリアの定義などを記入する。
  • PROCEDURE DIVISION では、計算機に実行させたい処理をCOBOLの命令により記入する。

第二章
IDENTIFICATION DIVISION（見出し部）
1、形式
*IDENTIFICATION DIVISION. *PROGRAM-ID. プログラム名． AUTHOR. プログラム作成者 DATE-COMPILED. コンパイル日付 DATE-WRITTEN. プログラム作成日 INSTALLATION. 会社名、課名、etc SECURITY. 情報の極秘等 REMARKS. プログラムの概要処理

＊ は省略不可、他は省略可能。コンパイル日付は機械の方でコンパイル時に入れてくれるので、プログラマーが記入する必要はない。記入した時には、機械の方の日付は無視される。

記入例
IDENTIFICATION    DIVISION.
PROGRAM-ID.       SS001601.
DATE-COMPILED.
REMARKS.          MIX DUMP.

尚、REMARKSは、項目中にスペースがあっても、2行になっても、全くプログラムにさしつかえはない。

第三章
ENVIRONMENT DIVISION（環境部）
1、形式
*ENVIRONMENT DIVISION. *CONFIGURATION SECTION. *SOURCE-COMPUTER. *OBJECT-COMPUTER. SPECIAL-NAMES. INPUT-OUTPUT SECTION. FILE-CONTROL. I-O-CONTROL.

＊ の4つは指定しなければならない。＊のない4つは、プログラム上あるいはファイルの都合上、指定せねばならないものもある。

記入例
ENVIRONMENT       DIVISION.
CONFIGURATION     SECTION.
SOURCE-COMPUTER.  IBM-370.
OBJECT-COMPUTER.  IBM-370.
SPECIAL-NAMES.    C01 IS F-FILE
INPUT-OUTPUT      SECTION.
FILE-CONTROL.
    SELECT INFL ASSIGN TO UT-S-INFL.
    SELECT OTFL ASSIGN TO UT-S-OTFL.
I-O-CONTROL.
    APPLY WRITE-ONLY ON OTFL.
(1) SPECIAL-NAMES

これは、プリントなどでファーストラインに名前を付けるものである。（C01のみ使用）

例えば、"C01 IS FIRST-LINE" と記入すると、チャネル01（C01）の名前をFIRST-LINEとすると定義する事である。これは、プロシジャーディビジョンでプリントファイルにWRITEする時使用される。BEFOREもしくはAFTERでFIRST-LINEと書くと命令が実行された後、もしくは前にプリンタのポインタは、TOPを指す。詳細はWRITE命令を参照。

(2) SOURCE-COMPUTER

この段落は文書化の働きしかしない。コンパイルする電子計算機について記述する。通常、IBM-9790. などの様に記述する。

(3) OBJECT-COMPUTER

SOURCE-COMPUTERと同じで実行する計算機について記述する。MEMORY SIZEやSEGMENT-LIMITなどのOPTIONがあるが、ここでは省略する。

(4) INPUT-OUTPUT SECTION

個々のファイルの定義。ファイルを入れる外部記憶媒体の識別（JCLのDDとの関連付け）、1つ又は2つ以上の入出力装置へのファイルの割り当てなどを定義するセクションで、FILE-CONTROL段落と、I-O-CONTROL段落がある。

(5) FILE-CONTROL

ファイルを入出力装置に割り当てる。

SELECT 文節 ASSIGN 文節 RESERVE 文節 FILE-LIMIT 文節 ACCESS MODE 文節 PROCESSING MODE 文節 ACTUAL KEY 文節 NOMINAL KEY 文節 RECORD KEY 文節 TRACK-AREA 文節 TRACK-LIMIT 文節
① SELECT 文節

SELECT文節は、プログラム中の個々のファイルに名前を与える為に使用される。

SELECT ファイル名

このファイル名で書いた名前は、DATA DIVISION中のFD又はSD項目を持っていなければならない。

② ASSIGN 文節

ASSIGN文節は、ファイルを外部媒体（JCL上のDD名）に割り当てるものである。

ASSIGN TO システム名

システム名の構成：クラス（－装置）－編成－名前

クラス説明装置番号例
DA大容量記憶装置—
UTユーティリティ（IBMでは主にこれ）2301, 2302, 2303, 2311, 2321, 2314 / 2400など
URユニットレコード1403, 1404, 1443など

UTスはURに割り当てられるファイルは標準順次編成でなければならない。DAは順次編成又は直接編成のいずれでもよい。

編成コード意味
S標準順次編成
D直接編成
WREWRITEを使用時の直接編成
R相対編成
I索引編成

名前は、1〜8文字までで示すDD名である。

③ RESERVE 文節

コンパイラーが割り当てられる入出力域（BUFF）の数をユーザーが修正できる様にするものである。

RESERVE { NO    } ALTERNATE [ AREA  ]
        { 整数  }            [ AREAS ]

整数で示される偶数だけBUFFが確保される。但し、順次アクセスにのみ有効。

④ FILE-LIMIT 文節

この文節は、コメントとしてあつかわれるので省略する。

FILE-LIMIT IS リテラル-1 THRU リテラル-2
⑤ ACCESS MODE 文節

ファイルのレコードをアクセスする方法を規定する。省略時は SEQUENTIALとみなされる。

ACCESS MODE IS { SEQUENTIAL }
               { RANDOM     }
⑥ PROCESSING MODE 文節

この文節は、指定してもコメントとして扱われる。

PROCESSING MODE IS SEQUENTIAL
⑦ ACTUAL KEY 文節

ランダム・アクセスの時には、指定しなければならない。データ名は、5〜259バイトの長さの固定長項目であり、DATA DIVISIONで指定しなければならない。

ACTUAL KEY IS データ名
⑧ NOMINAL KEY 文節

索引付ファイル及び相対ファイルをランダム・アクセスする時、指定しなければならない。データ名は、1〜255バイトの長さの固定長のWORKING-STORAGE SECTIONで項目を指定する事ができる。

NOMINAL KEY IS データ名
⑨ RECORD KEY 文節

索引ファイルをアクセスする為に使用する。データ名は、255バイト以下の固定長項目でなければならない。

RECORD KEY IS データ名
⑩ TRACK-AREA 文節

索引ファイルに対し、ランダム・アクセス方式でレコードを追加する場合、使用される。この文節を使用するとレコード追加の効率がよくなる。定義される区域は、8の倍数で、32760バイト以内。

TRACK-AREA IS { データ名 }
              { 整数    }
⑪ TRACK-LIMIT 文節

直接編成ファイルの作成時、初期値化すべき最後のトラックの相対番号を示すものである。

TRACK-LIMIT IS 整数 TRACK(S)
(6) I-O-CONTROL
I-O-CONTROL.
    RERUN 文節
    SAME AREA 文節
    MULTIPLE FILE TAPE 文節
    APPLY 文節
① RERUN 文節

RERUN文節は、チェックポイント・レコードをとる事を指定するものである。

RERUN ON システム名
EVERY { 整数          RECORD }
      { [END OF] { REEL }    }
                 { UNIT }    }
  • システム名は、チェックポイント・レコードが書かれるファイル。
  • ファイル名は、チェックポイント・レコードをどのファイルの為に取るのか、その目的のファイルを表わす。これは、DATA部で定義されていなければならない。
② SAME 文節

処理中に2つ以上のファイルが同じコア記憶域を使用することを指定する。

SAME [ SORT   ] AREA FOR ファイル名-1…n
     [ RECORD ]
③ MULTIPLE FILE TAPE 文節

これは文書化の為に使用。

MULTIPLE FILE TAPE CONTAINS ファイル名-1
POSITION 整数-1…n
④ APPLY 文節
(I)  APPLY WRITE-ONLY ON ファイル名-1…n
     Vモードのレコードをもつファイルをアウトファイルに対し使用する。
     この指定をした時のWRITE文は、
     "WRITE レコード名 FROM エリア名" の形をとらなければならない。
     指定しないと、ブロッキングの使用効率が非常に悪くなる。

(II) APPLY CORE-INDEX ON ファイル名-1…n
     ランダム・アクセスの索引付ファイルに対してのみ指定できる。

(1) FILE SECTION

ここでは、プログラム中で使用される外部データのDCBなどを記述する。1つのプログラム中で25個以内のファイル記述項目を書く事ができる。

A. ファイル記述項目（FD）

FD  ファイル名
    BLOCK CONTAINS 文節
    RECORD CONTAINS 文節
    RECORDING MODE 文節
    LABEL RECORD 文節
    VALUE OF 文節
    DATA RECORD 文節
    REPORT 文節
① BLOCK CONTAINS 文節

ここでは、物理レコードのブロック長を指定する。

BLOCK CONTAINS [整数-1 TO] { CHARACTERS }
                           { RECORDS    }

1レコード1ブロックのデータには、この文節を指定する必要はない。データがFIXの時は、整数-2だけを指定する。データがVARIABLEの時は、整数-2はMAXのレコード長を指定し、整数-1を指定する時はMINのレコード長を記入する。例えば、BLOCK CONTAINS 1 TO 3 RECORDS と指定すると、最小1レコード最大3レコードであるということを意味している。

② RECORD CONTAINS 文節

ここでは、データ・レコードの大きさを指定する。

RECORD CONTAINS [整数-1 TO] 整数-2 CHARACTERS

通常、整数-2を指定する。整数-2はMAXのレコードの大きさである。整数-1を指定する時は、データがVARIABLEの時で、レコードの最小値を指定する。

③ RECORDING MODE 文節

ここでは、F、U、V、Sを指定する事ができる。

RECORDING MODE IS モード
モード説明
Fファイル内、全てのレコードが同じ長さである。通常、各ブロックに入るレコード数は固定している。
Uレコードの長さは、固定長でも可変長でもよい。しかし、各ブロックには1レコードしか入らない。
Vレコードの長さは、固定長でも可変長でもよいが、それぞれ1つのブロックの中に1〜n個のレコードは収まっていなければならない。
Sレコードの長さは、固定長でも可変長でもよく、1レコードが1ブロックより大きくてもよい。

U、VモードはK索引付編成、および相対編成のファイルには指定できない。Sモードは、標準順次ファイル、又は直接ファイルに対して指定できる。

④ LABEL RECORD 文節

ここでは、ラベルの有無を指定するものである。

LABEL { RECORD IS  } { OMITTED      }
      { RECORD ARE } { STANDARD     }
                     { データ名-1…n }
  • OMITTED：ユニット・レコード装置に割り当てられているファイルに対して必ず指定しなければならない。（ただし、IBMではこれもSTANDARDで処理できる）
  • STANDARD：ファイルに数個のラベルがついており、システム仕様に従っていることを指定する。索引付編成はSTANDARDを指定しなければならない。
  • データ名-1…n：ユーザーラベルで標準外ラベルである。
⑤ VALUE OF 文節

この文節は、コメントとして扱われるので指定する必要はない。

VALUE OF データ名-1 IS { データ名-2  }
                      { リテラル-1  }
⑥ DATA RECORD 文節

FD文の後で書くデータレコードの名前を指定する。データ名を複数指定する時は、01レベルでその分をとらなければならない。

DATA { RECORD IS  } データ名-1…n
     { RECORD ARE }
(2) データ記述項目 / WORKING-STORAGE SECTION

データ記述項目は、後で述べる WORKING-STORAGE SECTIONで説明することと重なる部分が多いので、簡単に述べる事にする。

レベル番号 { データ名 } PICTURE句
          { FILLER  }

レベル番号は、データの内容にレベル付けをするもので01〜49まで指定できる。通常、01、05、10…の順で付けていく事が多い。ファイルの項目のDATA RECORD文節で指定したDATA名をここで01レベルで定義しなければならない。

レベル番号の特殊値
レベル番号名称特徴
66再編成項目データ項目のグループを再編成する
77独立項目下位レベルを持たない。セクション先頭で定義。
88条件項目エリアを持たない。上位レベルの条件を定義。
01〜49一般項目通常 01, 05, 10… の順で付ける。
例 — DATA RECORD IS IN-RECと定義済み
01  IN-REC.
  05 IN-KUBUN              PIC X(2).
  05 IN-NAIYO.
    10 IN-NAIYO-1          PIC X(5).
    10 IN-NAIYO-2          PIC X(10).
    10 FILLER              PIC X(20).

これは、IN-RECという名前のレコードがあり、37バイトであるという事を示している。その内訳は、IN-KUBUNという名前のエリアが2バイトで、IN-NAIYOというエリアの中にIN-NAIYO-1というエリアが5バイト、IN-NAIYO-2というエリアが10バイトあるという事である。通常は、レコード名は01レベルでとり、PICTURE句を付け、内訳は書かない。実際の内訳は、WORKING-STORAGE SECTIONで記述する形が多く使用されている。

① WORKING-STORAGE SECTION

ここでは、プログラム中でワークとして使用するエリア、INPUTやOUTPUTのエリアをコピーしたり指定したりするエリア、カウンターやスイッチのエリアを定義するエリアである。

記述の方法は、データ記述項目と同じであるがレベルに特別な物がある。66、77、88である。77レベルは、記述する時は、このセクションの最初で定義しなければならない。

ア 77レベル（独立項目）

このレベルは、下位レベルをもたない。故に独立項目と呼ばれる（ただし88レベルを除く）。

イ 88レベル（条件項目）

このレベルの項目はエリアをもたない。上位レベルでエリアを定義し、88レベルでその条件を示す。

例
77  FILE-SIGN  PIC X.
  88 EOF-SIGN   VALUE "E".

上記の様に定義して、"E" という文字をFILE-SIGNへ移送する。通常このエリアに"E"が入ったかどうかを聞く為には、IF FILE-SIGN="E" と記述するが88レベルを記述している為、IF EOF-SIGN と書くだけでよい。="E" というのは、書く必要がない。なぜなら、VALUE "E"と定義している為、PIC Xのエリアに"E"という文字が入った時だけ条件が満たされる。これは、各自で実際にやってみると納得出来るのだが、……

ウ 66レベル（再編成項目）

このレベルの項目は、データ項目のグループを再編成する項目であるがここでは説明を除く。

② PICTURE 句

この句は、エリアの長さTYPEなどを指定する句である。尚PICTUREは、PICと省略できる。

PICTUREのTYPEには、9TYPE、ATYPE、XTYPE、及び編集TYPEがある。

ア 9-TYPE（数字項目）

PIC 99. という様に指定する。尚、長さを（）で囲んで指定する事ができる。PIC 9(2). これは、どのTYPEでも同じである。このエリア数字項目であり、0〜9以外の文字を移送する事はできない。（COMPUTATIONAL — 計算のみ）

X TYPEからの移送に注意
PIC X(5).         PIC 9(5).
    ↓不可              ↓可
ABC△△  →×→  △△△△△
12345   →○→  12345

上記の様にX TYPEからの移送には、十分、注意しなければならない。

小数点の指定

計算を行なう上で小数点は必要である。この小数点の指定には2種類あり、エリアをとらない仮想小数点とエリア1バイトを必要とする実小数点である。

種類指定バイト数特徴
仮想小数点PIC 999V99.5バイト小数点があるとみなされる。エリア消費なし。
実小数点PIC 999.99.6バイトエリアが1バイト確保される。
サインの指定

計算上＋、－のサインが必要な時がある。こんな時には"S"という文字をつけて表わす。PIC S99. これは、1バイトのエリアがとられる。

ゾーンとパックと2進数

2バイトエリアに"11"という数字を移送した結果を比べてみよう。

ゾーン   F1 F1
パック    0  1 1C
2進      0  0 0B
         ←1バイト→

まずゾーン形式は、F1F1という形で入っているが、F1というものが通常1と呼んでいるものである。マシンの中では、1バイトは8ビットである。8ビットの上位4ビットは1がすべてFとされる。その為ゾーンの2バイトでは、MAX99までしか入れる事はできない。

ところが、パック形式だと、このFが除かれた形で作られる。そして、最後の4ビットが"＋"、"－"を表わす。C、Fはプラス、Dはマイナスである。ゾーンのデータにおいてサイン（＋、－）は最後の1バイトの内、上位4ビットで表わされる。その4ビットはパックに準ずる。次に2進数だがこれは、人間の目に表わしやすいように16進数表示として表われる。この2進数のサインは、エリアの最上位のビットで表わされる。このビットが1ならばマイナス、0ならばプラスである。

形式指定例用途

パックPIC S9(3) COMP-3.サイズ（桁数）が大きいもの向き
2進数PIC S9(3) COMP SYNC.カウンターetcに最適・効率良い
境界について（SYNC）

2進でCOMPとCOMP SYNCと2つ書いたのは訳がある。COMPという指定で2進のエリアだという事を示すがSYNCと指定すると境界が合わせられる。

2バイト単位のエリアの境界をハーフワード境界、4バイト単位のエリアの境界をフルワード境界、8バイト単位のエリアの境界をダブルワード境界と呼ぶ。この境界は、COBOLではあまり考える必要はないが、アセンブラだと必要になるのでぜひ覚えておいてほしい。

   又は

     05 CTR-OUT          PIC S9(7).

④ JUST RIGHT 句

⑤ REDEFINE 文節

この文節は、一度定義したエリアに対して違った形で定義し直すものであり、新たにエリアは取れない。あくまでも同じエリアである。

定義方法
05  A              PIC X(10).
05  A-R REDEFINES A.
  10 B             PIC 9(5).
  10 C             PIC S9(5).
  10 D             PIC X(1).
05  A-RR REDEFINES A.
  10 E             PIC X(3).

上記の様に何度でも再定義してかまわない。再定義するバイト数が再定義されるエリアのバイト数よりも大きくする事は出来ないが、小さい分には構わない。上述の例では、エリアを使用する時にA、B、Cなど、どれを参照するかによって、エリアのもつTYPEが決定される。このREDEFINES文節は日付によく使われる。

日付処理の応用例（YYMMDD = 年月日）
05  A-YYMMDD.
  10 A-YYMM.
    15 A-YY                PIC X(2).
    15 A-MM                PIC X(2).
  10 A-DD                  PIC X(2).
05  A-YYMMDD-R REDEFINES A-YYMMDD.
  10 A-YY-R                PIC 9(2).
  10 A-MMDD.
    15 A-MM-R              PIC 9(2).
    15 A-DD-R              PIC 9(2).

上記の様に指定すると同じエリアをX-TYPEでも9-TYPEでも使用できる。

⑥ OCCURS 文節（テーブル）

この文節は反復するデータを定義するものである。OCCURS項目で作成されるテーブルは3次元まで許される。

OCCURS 整数 TIMES (DEPENDING ON データ名-1) { ASCENDING } KEY IS データ名-2 { DESCENDING } INDEXED BY 指標名
例1 — 基本テーブル（30個）
05  A  OCCURS 30 TIMES
       INDEXED BY A-X1.
  10 B  PIC X(1).

-- Bというエリアが30個あり、A-X1というインデックスで参照できる
-- B(1) B(2) あるいは B(A-X1) という使い方をする
例2 — KEYで昇順定義（SEARCHと連携）
05  A  OCCURS 30 TIMES
       ASCENDING KEY IS A-KEY
       INDEXED BY A-X1.
  10 A-KEY          PIC X(3).
  10 A-NAIYO        PIC X(10).

-- A-KEYがエリアの1番目から30番目まで昇順であると定義
-- SEARCHという命令に関連してくる
DEPENDING ON について

この句を指定しないとテーブルの長さがわからない時に指定する。VBデータなどの指定時には必要である。

例3 — 3次元テーブル（3×5×2=30個、600バイト）
05  A  OCCURS 3 TIMES
       INDEXED BY A-X1.
  10 B  OCCURS 5 TIMES
         INDEXED BY B-X1.
    15 C  OCCURS 2 TIMES
           INDEXED BY C-X1.
      20 D  PIC X(20).

-- D(1, 1, 1) または D(A-X1, B-X1, C-X1) の様に参照
例4 — VALUEとREDEFINEを組み合わせた文字テーブル
05  A            PIC X(10)
    VALUE        "ABCDEFGHIJ".
05  A-R REDEFINES A.
  10 B  OCCURS 10 TIMES
         INDEXED BY B-X1.
    15 C  PIC X(1).

-- C(3)は"C"であり、B-X1に5をSETしてやれば、C(B-X1)は"E"である

この様なテーブルは、VALUE句をもっているエリアをREDEFINEしてテーブルにしたり、集計用のエリアとして定義する事が多い。

(3) LINKAGE SECTION

ここでは、外部から渡されてくるデータ（パラメータ）、上位モジュールから渡されてくるデータを定義する場所である。基本的には、WORKING-STORAGE SECTIONの定義方法と同じである。

ただし、パラメータとして渡ってくるエリアを定義する時は、DATAの他に、そのDATAの長さが入ってくるエリア2バイトを定義しなければならない。

01  PARM.
  05 PARM-LL             PIC 9(3) COMP.
  05 PARM-YMD            PIC X(6).

これは、パラメータとして入ってくるのは、PARM-YMDで、6バイトである。この6バイトという長さがPARM-LLへ付加されてプログラム中へ入ってくる。このLLのエリアは、名前をつける必要はなく、FILLER PIC X(2). でもよい。

6、COMPUTE

この命令は、前途した、ADD、SUBTRACT、MULTIPLY、DIVIDEなどの機能を算術文を用いて指定できる。

記号意味優先度
＊＊べき乗高
＊ ／乗算・除算↑
＋ －加算・減算低
（　）優先度の指定最高
COMPUTE 識別名-1 [ROUNDED]
  = （識別名-2 | リテラル | 算術演算式）
例 — C = (A-B)/(B+E) × D
COMPUTE C = ((A+B) / (B-E)) * D

したがって通常使用している算術文がほぼ同じ形で書ける事がわかるだろう。ただし、COMPUTE命令には余りを求めるオプションはない。余りを必要とする時にはDIVIDE命令を使用しなければならない。

受け項目（＝の左側）は数字編集項目であってもかまわない（PIC ZZZ. etc）。命令の実行順序は（）で囲まれている部分が先ず実行され、次にべき乗、次に乗算又は除算、次に加算又は減算の順で、同レベルの場合は左から順に処理される。

複雑な式の比較 — A = B×C×D⁶ + 6 - E
【COMPUTE使用】
COMPUTE A = B * C * D ** 6 + 6 - E.

【個別命令使用（同等処理）】
MULTIPLY D BY D GIVING A.   ← （4回繰り返す）
MULTIPLY B BY A.
MULTIPLY C BY A.
ADD      6  TO A.
SUBTRACT E  FROM A.

ここで分かる様に複雑な計算式にはCOMPUTE命令の方が便利である。又、他の命令を組み合わせると全体の式がイメージしにくいという欠点もある。

ON SIZE ERROR オプション

COMPUTE, ADD, SUBTRACT, MULTIPLY, DIVIDE命令には、受け項目のサイズが小さくてオーバーフローした場合のオプションがある。

MULTIPLY A BY B
  ON SIZE ERR GO TO ERR-SHORI.

BのエリアがオーバーフローしたらERR-SHORIというルーチンへ飛ぶ。
7、IF 文

IF文は、条件によってそれまでの処理を変える事ができる。

IF   条件   ステートメント-1   NEXT SENTENCE
ELSE        ステートメント-2   NEXT SENTENCE

条件が真であればステートメント-1が実行され、偽であればステートメント-2が実行される。

例
IF A = B

ELSE
  NEXT SENTENCE.

ネスティングの例

    IF C = D

    ELSE

8、READ

この命令はファイルを実際にプログラム内に読込んでくる命令である。このREAD命令を実行する前に、ファイルに対してOPEN命令が実行されていなければならない。実行されていないと、ABEND=U3706などでプログラムは異常終了する。

READ ファイル名 [INTO データ名]
  AT END 命令ステートメント.
例
READ INFL1 INTO IN-DATA
  AT END
    MOVE '1' TO SW-EOF
    GO TO READ-END

この命令では、INFL1が読まれ1件のデータがWORKING-STORAGE SECTIONで定義してあるIN-DATAというエリアへ入れられる。尚、ファイルがエンドの場合は、SW-EOFに'1'をたて、READ-ENDという段落名の所へ飛んでいく。

INTOを使わないと、FILE SECTIONで定義した01レベルのエリア内にデータは読み込まれている。もちろん、INTOを使っても、このエリアにはデータは入っている。すなわちINTOオプションは、READ ＋ MOVE に相当する。

9、MOVE

この命令は記憶域のある区域から1つ又は2つ以上の区域へデータを移す為に用いられる。

MOVE 識別名-1 TO 識別名-2 (n)
例
MOVE ZERO TO A B C.   → A、B、Cの内容がゼロクリアーされる。
MOVE A TO B.          → Aの内容がBに移される。

MOVEステートメントは、インデックスには使えない。インデックスには、後述のSET命令を使う。

10、SET

この命令は、インデックスに値をセットしたり、加算、減算をするものである。この命令では、MOVEと違い、右側のものが左側へセットされる。

SET INDEX名   TO    識別名-1
SET   〃      UP BY   〃
SET   〃    DOWN BY   〃
例
SET IDX1 TO 1.        → IDX1というインデックスに1がセットされる。
SET IDX1 UP BY 1.     → IDX1というインデックスが＋1される。
SET IDX1 DOWN BY 3.   → IDX1というインデックスが－3される。
11、PERFORM

コボルのプログラムを組む上で、処理別にセグメント化すると見やすくなるだけでなく、修正、デバッグも容易になる。このセグメント化した処理を連結する時に、このPERFORM命令を使用する。

【基本形式】
PERFORM 処理手順名-1 [THRU 処理手順名-2]
                    [識別名-1 TIMES]

【条件付き】
PERFORM 処理手順名-1 [THRU] 処理手順名-2
  UNTIL 条件

【VARYING（多次元テーブル処理）】
PERFORM 処理手順名-1 THRU 処理手順名-2
  VARYING 指標名-1 FROM 指標名-2 UNTIL 条件-1
  BY 指標名-3
  [AFTER 指標名-4 FROM 指標名-5
  BY 指標名-6 UNTIL 条件-2
    [AFTER 指標名-7 FROM 指標名-8
    BY 識別名-9 UNTIL 条件-3 ]]
基本的なPERFORMの使い方
PERFORM S03-READ THRU S03-EXIT.

S03-READ.         このPERFORM命令の所へきたら、
  …               S03-READからS03-EXITまでの中の
S03-EXIT.         処理を行なってから、PERFORM命令
  EXIT.           の次の命令を行なう。

一般に、メイン処理は、PERFORM命令とIF文で組み立てられる事が多い。尚、PERFORMした先から、別のセグメントへブランチすることは、望ましくない（後からの解析がやりにくくなる）。

望ましくない例
S04-SHORI.
  …
  GO TO S05-SUB   ← 別セグメントへのGO TOは望ましくない
S04-EXIT.
  EXIT.

S05-SUB.          ← GO TO文はそのセグメント内にとどまる方が望ましい
S05-EXIT.
  EXIT.
UNTIL条件付き — ファイルエンドまで繰り返す
PERFORM S04-SHORI THRU S04-EXIT
  UNTIL SW-END = 'E'.

S04-SHORI.
  READ INFL
    AT END
      MOVE 'E' TO SW-END
      GO TO S04-EXIT.
  …
S04-EXIT.
  EXIT.

INFLをREADし、ファイルエンドになるまで
S04-SHORIからS04-EXITまでを繰り返す。
VARYING — 2次元テーブル処理の例
PERFORM S05-SHORI THRU S05-EXIT
  VARYING IDX1 FROM 1
    BY 10 UNTIL A > B
  AFTER IDX2 FROM 1
    BY 10 UNTIL B > C.

①IDX1とIDX2が1にSETされている。
②条件A＞Bが調べられ真ならば、この命令の次のステートメントへ移る。
③偽ならば、条件B＞Cが調べられ、IDX2は1にSETされ、IDX1が1UPされる。
④IDX1が10を超えたら、次のステートメントへ移る。
⑤超えていなければ、②から④が繰り返される。
⑥条件B＞Cが偽ならば、PERFORMのS05-SHORIからS05-EXITが1回実行される。
⑦IDX2の値が1UPされ、又条件B＞Cが調べられる。
⑧以上の処理が繰り返されるわけである。

この様な事から、テーブル処理に向いているといえる。

この命令は現在、処理している位置から、他の位置へブランチさせる命令である。GO TO文は、1つの処理内で使うのが望ましい。他の処理へブランチさせても、プログラム的には問題無いが、デバッグ修正等が困難になる。

GO TO 処理手順名
単純ブランチの例
S04-SHORI.
  GO TO S04-02.
S04-01.
  GO TO S04-03.
S04-02.
  GO TO S04-01.
S04-03.
S04-EXIT.
  EXIT.

上で説明したのは、単純ブランチだが、ある値の数によって、どこへブランチするかという命令がある。

【計算型GO TO — DEPENDING ON】
GO TO 処理手順名-1
      処理手順名-2
      処理手順名-n DEPENDING ON 識別名

これは、識別名の内容が、1であれば、処理手順-1へブランチする。又、該当が無ければ、このGO TO文は実行されないので、次のステートメントへ移る。

計算型GO TO の例
MOVE A TO WK-DEP.

     S03-02
     S03-03 DEPENDING ON WK-DEP.

S03-01.  ここでWK-DEPというのは、WORKING
  …      STORAGE SECTION で定義済みの
S03-02.  9-TYPEのエリアである。
  …      このWK-DEPに1〜3の値が入っていれば、
S03-03.  S03-01、S03-02、S03-03へ
  …      それぞれブランチする。
13、OPEN

この命令は、ファイルをREADあるいはWRITE出来るようにあらかじめ開いておくという命令であり、READ, WRITEの前に実行しておかなければならない。尚、1度OPENすると、CLOSE命令を実行するまではOPEN命令は実行できない。通常、プログラム中では、頭で（INITIAL処理で）行なう事が多い。

OPEN INPUT   ファイル名-1…(n)
OPEN OUTPUT  ファイル名-2…(n)
OPEN I-O     ファイル名-3…(n)

ファイルをどのような使用の為に開くかという指定でINPUT（READだけ）、OUTPUT（WRITEだけ）、I-O（両方）というのを指定しなければならない。

I-OでREAD/WRITEをする時はインプットとして読まれたデータに書いていくので、インプットデータは残らない。この点に気を付けて欲しい。

14、CLOSE

この命令は、既に開かれているファイルを閉じる命令である。この命令を実行する前には、必ずOPEN命令が実行されていなければならない。CLOSE命令には、INPUT, OUTPUTetcの指定はいらない。尚、CLOSE命令を実行した後、FILEのREADあるいはWRITEを行う時には、OPEN命令を実行しなければならない。

CLOSE ファイル名-1…(n)
例
CLOSE INFL OUTFL   ← INFL,OUTFLと名付けられたファイルを閉じる。

このCLOSE命令において、リワインドさせるとか、させないとかetc、オプションがいくつかあるが、ここでは省略する。

15、WRITE

この命令は、OUTPUT、もしくはI-Oで開かれたファイルへ、書き出しを行う命令である。

【リスト以外のファイル】
WRITE レコード名 [FROM 識別名]

【リストへのWRITE（改行制御あり）】
WRITE レコード名 [FROM 識別名]
  [BEFORE] ADVANCING 識別名 LINES
  [AFTER ]
（通常ADVANCINGとLINESという語は省略して使う）
WRITEとFROMの等価性
WRITE OUT-REC FROM OUT-DATA.

← 以下と同じ意味（MOVE + WRITE）

MOVE  OUT-DATA TO OUT-REC.
WRITE OUT-REC.

今度は、リストにWRITEする方法であるが、大きく分けて、2種類の方法がある。1つは、1ラインプリントした後で改行を行う（BEFORE）方法、もう1つは、改行を行った後プリント（AFTER）する方法である。

この命令は、識別名の中に入っている数の分だけ、ラインを飛ばすという事であり、ここにSPECIAL-NAMESの所で指定したC01 IS 〜 の名前を使うと、改頁されてプリントできる行の最初の行を指す。

BEFORE と AFTER の違い（PR-RECの内容 = "*** テスト プログラム ケッカ ***"）
WRITE PR-REC BEFORE 2 の場合：
  "*** テスト プログラム ケッカ ***"  ← P（書き出し後、2+1ライン先へ）
  （空白行）
                                      ← P'（ここで止まる）

WRITE PR-REC AFTER 2 の場合：
  スペース（2ライン先へ先に移動）
  "*** テスト プログラム ケッカ ***"  ← P'（ここで止まる）

効率としては、BEFOREの方が良い。なぜなら、プリントしてプリンタが改行している間に、プログラムでは次にプリントする内容をセットできるからである。尚、1つのプログラム中では、どちらかに統一した方が、間違いが少なくていい。

16、DISPLAY

この命令は、SYSOUT、SYSPUNCH、CONSOLE上に、データを書き込む命令で、プログラム上でファイルは持たない。

DISPLAY 識別名-1…(n) [UPON { CONSOLE  }]
                           { SYSOUT   }
                           { SYSPUNCH }
                           { SYSPCH   }

UPON句が省略されていると、SYSOUTとみなされる。

出力先最大桁数
SYSOUT120桁
CONSOLE100桁
SYSPUNCH72桁
例
DISPLAY "*** PROGRAM ERR ***" UPON CONSOLE.
→ コンソール上に "*** PROGRAM ERR ***" と表示される。

DISPLAY "ERROR△△" "CODE=" WK-CODE.
→ WK-CODEに '001' が入っていると仮定すると、
  SYSOUT上に "ERROR△△CODE=001" とプリントされる。

CONSOLE以外は、JCL上でDDカードを指定しておかなければならない。DISPLAYは、入出力件数を出力する時によく使われる。

17、SEARCH

この命令は、テーブルで取られたエリア内から、あるKEYに基づいて、必要なデータを探し出す命令である。SEARCHを使わずにIFでLOOPさせるやり方もある。

SEARCH テーブル名 [AT END 命令ステートメント-1]
  WHEN 条件 命令ステートメント-2

テーブル名は、エリアの上で、OCCURS句が付いている項目である。
SEARCHを使った場合
05  A-OCCUR  OCCURS 100 TIMES
             INDEXED BY A-X1.
  10 A-KEY             PIC X(3).
  10 A-NAIYO           PIC X(25).
05  WK-KEY             PIC X(3).
05  WK-DATA            PIC X(25).

SET A-X1 TO 1.         ← 必ず事前にセット
SEARCH A-OCCUR
  AT END GO TO SEARCH-END
WHEN WK-KEY = A-KEY(A-X1)
  MOVE A-NAIYO(A-X1) TO WK-DATA.

A-OCCURのA-KEYのn番目がWK-KEYと等しいものを探し出して、
そのn番目のA-NAIYOをWK-DATAへ移す。
条件に合うものが無ければ、SEARCH-ENDへブランチする。
IFループで同等処理を記述した場合（比較）
SET A-X1 TO 1.
S03-SEARCH.
IF A-X1 > 100
  GO TO S03-SEARC-END
ELSE
  IF A-KEY(A-X1) = WK-KEY
    MOVE 1-NAIYO(A-X1) TO WK-DATA
  ELSE
    SET A-X1 UP BY 1
    GO TO S03-SEARCH.

前頁のサーチ処理と比べると、サーチの方がステートメント数が少なくてすみ、S03-SEARCHという処理手順名をとる必要が無い事がわかる。どちらを使うかは、ケースBYケースで使い分けて欲しい。

4、マッチング処理の説明

マッチングとは、複数のファイルをあるKEYによって照合させ、同一KEY同士の処理を行ない、ファイルを更新する事をいう。一般には、旧（更新前）マスターと、トランザクションファイル（取引ファイル）を照合させ、トランザクションファイルの内容によって、マスターの内容を更新して、新マスターを作成する。その際、エラーのデータはエラーファイルに出力し、同時にリスト件数表を出力する。

例えば、マスターファイルのKEYと、トランザクションのKEYを、B表の様に仮定すると、マスターファイルの1件目に更新をかけようとすると、トランザクションの1件目と2件目をREADしなければならない。又、3件目のトランザクションの'05'というKEYは、マスターの方にはない為、新しくマスターの'04'と'06'の間にインサートする事になる。こうして、新マスターを作成する。

B表 — マスターとトランザクションの照合
件数  マスター  トランザクション   処理
  1      01          01       →  01 （更新をかける）
  2      02          01       →  02 （2件目で更新）
  3      03          05       →  03 （該当なし、マスターそのまま）
  4      04          06       →  04 （同上）
  5      06          06       →  (05)← マスターにないからインサート
  6      07          07       →  06 （更新）
  7      09          08
  8      10          09

したがって、通常のマスター更新処理の新マスターは、件数は増える事はあっても減る事はない。（ただし、DELETE処理が入っていれば、この限りではない）

フローの1番最後のN:Nについて

  • N:Nのマッチング処理で、マスター及びトランザクションのKEYの両方とも、同一KEYの個数のMAXがまるで分からない時、このフローの様にオープン、クローズを繰り返し、あたかも、1:Nのマッチング処理を行うかの様に処理を行う。このSTR1、STR2というのは、KEYが変わる直前のKEYの値をストアしておくエリアである。
  • N:Nのマッチング処理で、マスターもしくはトランザクションのKEYのどちらかのKEYのMAXがわかっていて、且つ、RECORD-LENGTHとMAX件数を乗じた値のレングスが、ワーク（プログラム上で）上でとりうる値であれば、まずKEYが変わるまでワーク上へストアし続け、KEYが変わった時点でそのワークと、ファイルのマッチング処理を行う。これは、1:Nのマッチング処理と同様の処理を行なうことが出来る。このフローは、各自で作成してみるとよい。
  • N:Nのマッチング処理というのはあまりないので、1:Nのフローを完全にマスターした方がよい。N:Nは、1:Nの応用である。又、1:1:1、1:1:N、の様な多数ファイルのマッチング処理も、基本は1:Nである。
5、コントロールブレークのフロー例

プリントルーチン：53ラインを超えたら見出しを打つ。

ライン数 > 53 ──YES──→ 見出し処理（改頁・見出し印字・カウンタ初期化） ↓ データセット処理（プリントエリアへデータを移送） ↓ PRINT処理（WRITE・ライン数カウンタ+1・エリアクリア）

このフローは、プリントルーチンの一部である。ライン数をカウントして、53ラインをこえたら改頁して見出しを打つというコントロールブレイクの基本である。この形がコントロールブレイクの基本である。非常に簡単なのだが、様々な処理が入ってくると改頁のタイミングというものは難しくなってくる。

ここではTSOの廻わりのファイルと、TSOでテストする場合とJCLとの違い、コマンドプロシジャーの基本的なものの作成方法を簡単に述べる。詳細はプログラマーズハンドブックを参照して頂きたい。

TSOのLOGON

LOGONとは、ユーザーがワークを確保して、我々の作業が行える様にする第1番目のコマンドである。

LOGON USER-ID/PASSWORD [↵]

例：LOGON @QAKOBA/1111 [↵]

このコマンドを入れるとTSOの画面は、READYになり使用可能となる。

4、JCLでのテストとTSOでのテストの違い
JCLによるテスト記述例
// SAMPLE       JOB  NSD,MSGLEVEL=1
// JOBLIB        DD   DSN=TESTLIB2,DISP=SHR
// STEP1        EXEC  PGM=SAMPLE,PARM='8106'
// INFL          DD   DSN=TEST.DATA,
//                    DCB=(BLKSIZE=1000,LRECL=100,RECFM=FB),
//                    VOL=SER=DTF005,UNIT=3350,
//                    DISP=SHR
// PRINT         DD   SYSOUT=A
// SYSOUT        DD   SYSOUT=A
// SYSUDUMP      DD   SYSOUT=A
TSOコマンドによる同等処理
FREE F(INFL,PRINT,SYSOUT)
ALLOC F(INFL)DA('TEST.DATA')VOL(DTF005)-UNIT(3350)SHR
ALLOC F(PRINT)-DA(*)
ALLOC F(SYSOUT)-DA(*)
TEST 'TESTLIB2(SAMPLE)''8106'

これだけKEYINするとTSO画面上にTESTという文字が出てくる。ここでGOというコマンドを入れるとプログラムは作動する。テストがうまく行くと結果が画面に現れる。これらのコマンドを一回ずつKEYINするのは非常に大変である。そこでコマンドプロシジャーというのが用意されている。これは、TSOワーク上にXX.CLISTという形で作る事が出来る。

6、CLISTの作り方

前頁のモード関係図を見てもらえば、モードの上下関係は大体分かると思う。TSO画面上にREADYと出ていたら、何もやっていないという事である。さて、コマンドプロシジャーの作り方を述べよう。

作成手順
READY状態で：
EDIT MIHON.CLIST NEW [E]   ← 何という名前でもよい（8桁以内）

画面に "INPUT" と表示され 000010 が出る。
前頁でテストする為に入れた KEY をそのまま1ラインずつ KEY IN する：

INPUT
000010  FREE F(INFL,PRINT,SYSOUT) [E]
000020  ALLOC F(INFL) DA('TEST.DATA') - [E]
          （中略）
000060  TEST 'TESTLIB2(SANPLE)''8106' [E]
000070  [E]

ENTER-KEY を押すと INPUTモード → EDITモード
画面に "EDIT" と表示される。

END SAVE[E] とKEY IN する。
→ モードは READY になる。
実行方法
EX MIHON [E]   ← これを入力するだけでTESTモードになる。

※ このコマンドプロシジャーをTSTPROCに登録すれば、
   EXをつけないで MIHON と打ち込むだけで作動する。

これが、最も基本的なコマンドプロシジャーである。このコマンドプロシジャー内で様々な処理を行わせる事もできるが（IF＆SET etsを使って）それは省略しておく。ここでは、JCLとコマンドプロシジャーの違いを知っておいてもらいたい。
