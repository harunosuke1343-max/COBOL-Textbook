1COBOLの概説

COBOLの単位

語はCOBOL予約語、あるいはプログラマーによって定義される語のいずれかである。予約語はCOBOLコンパイラーに対し、特定の統語上意味を持っている。プログラマーによって定義される語は、データ名やプログラム名などの項目で名前を付ける際はCOBOLの規則に従わなければならない。

4つのDIVISION

各DIVISIONは論理的な順序に配置される。DIVISIONのコーディングの順序は下記のとおりである。

COBOL — DIVISION構造
IDENTIFICATION  DIVISION.    <─ 見出し部
ENVIRONMENT     DIVISION.    <─ 環境部
DATA            DIVISION.    <─ データ部
PROCEDURE       DIVISION.    <─ 手続き部
  • IDENTIFICATION DIVISION — プログラム名、プログラム作成者、作成日などを記入する。
  • ENVIRONMENT DIVISION — プログラムを処理する具体的な計算機の構成に関する情報、JCLのDD名とDCB名の対応づけなどを記入する。
  • DATA DIVISION — プログラムで扱う全てのデータの形式・性質、及び作業用エリアとして使用するエリアの定義などを記入する。
  • PROCEDURE DIVISION — 計算機に実行させたい処理をCOBOLの命令により記入する。

文字セット

51種類の文字から構成される。

文字意味
0, 1〜9数字
A, B〜Z英字
△スペース（空白）
＋正の符号
−負の符号（ハイフン）
＊星印（アスタリスク）
／斜線（スラッシュ）
＝等号
¥通貨記号
：コロン
；セミコロン
．ピリオド（小数点）
" または '引用符（IBMでは '）
（ ）括弧
＞ ＜不等号

語の中に使用される文字:
0〜9, A〜Z, −（ハイフン）は語の始めと終わりには使用できない。桁数は30桁以内。

COBOL — 語名の例
例  S02-INITIAL
    WK-FROM.
    COUNTER-AREA  etc

2IDENTIFICATION DIVISION（見出し部）

形式と記入例

COBOL — IDENTIFICATION DIVISION 形式
IDENTIFICATION DIVISION.
PROGRAM-ID.       プログラム名.
AUTHOR.           プログラム作成者
DATE-COMPILED.    コンパイル日付
DATE-WRITTEN.     プログラム作成日
INSTALLATION.     会社名、課名、etc
SECURITY.         情報の極秘等
REMARKS.          プログラムの概要処理

  ＊ 付きは省略不可、他は省略可能

DATE-COMPILEDはコンパイル時に機械側でセットされるので、プログラマーが記入する必要はない。記入した場合には機械側の日付は無視される。

記入例

COBOL — SS001601
IDENTIFICATION DIVISION.
PROGRAM-ID.  SS001601.
DATE-COMPILED.
REMARKS.     MIX DUMP.

REMARKSは項目中にスペースがあっても、2行になっても、全くプログラムに差し支えない。

3ENVIRONMENT DIVISION（環境部）

形式

COBOL — ENVIRONMENT DIVISION 形式
ENVIRONMENT    DIVISION.
CONFIGURATION  SECTION.
SOURCE-COMPUTER.
OBJECT-COMPUTER.
SPECIAL-NAMES.
INPUT-OUTPUT   SECTION.
FILE-CONTROL.
I-O-CONTROL.

  最初の4つは指定必須。他は必要に応じて指定。

記入例

COBOL — ENVIRONMENT 記入例
ENVIRONMENT    DIVISION.
CONFIGURATION  SECTION.
SOURCE-COMPUTER. IBM-370.
OBJECT-COMPUTER. IBM-370.
SPECIAL-NAMES.  C01 IS F-FILE.
INPUT-OUTPUT   SECTION.
FILE-CONTROL.
  SELECT INFL ASSIGN TO UT-S-INFL.
  SELECT OTFL ASSIGN TO UT-S-OTFL.
I-O-CONTROL.
  APPLY WRITE-ONLY ON OTFL.

SPECIAL-NAMES

プリントなどでファーストラインに名前を付けるものである（C01のみ使用）。例えば C01 IS FIRST-LINE と記入すると、チャネル01（C01）の名前を FIRST-LINE と定義する。PROCEDURE DIVISIONでプリントファイルにWRITEする際に使用される。BEFOREまたはAFTERでFIRST-LINEと書くと、命令が実行された後または前にプリンタのポインタはTOPを指す。

SOURCE-COMPUTER / OBJECT-COMPUTER

これらは文書化の働きをする。コンパイルする/実行する計算機について記述する（通常 IBM-9790 など）。

INPUT-OUTPUT SECTION

個々のファイルの定義。ファイルを入れる外部記憶媒体の識別（JCLのDDとの関連付け）。FILE-CONTROL段落とI-O-CONTROL段落がある。

FILE-CONTROL

ファイルを入出力装置に割り当てる。

① SELECT文節

プログラム中の個々のファイルに名前を与える。

構文
SELECT ファイル名

このファイル名はDATA DIVISION中のFD又はSD項目を持っていなければならない。

② ASSIGN文節

ファイルを外部媒体（JCL上のDD名）に割り当てる。

構文
ASSIGN TO システム名
構成要素説明
クラスDA（大容量記憶装置）、UT（ユーティリティ）、UR（ユニットレコード）
装置通常指定しない。UT: 2301/2302/2314等、UR: 1403/1404等
編成S: 標準順次編成、D: 直接編成、W: REWRITE使用時、R: 相対編成、I: 索引編成
名前1〜8文字のDD名

③ RESERVE文節

構文
RESERVE { NO   } ALTERNATE [ AREA  ]
        { 整数 }           [ AREAS ]

整数で示される数だけBUFFが確保される。順次アクセスにのみ有効。

⑤ ACCESS MODE文節

構文
ACCESS MODE IS { SEQUENTIAL }
               { RANDOM     }

省略時はSEQUENTIALとみなされる。

⑦ ACTUAL KEY文節

構文
ACTUAL KEY IS データ名

ランダム・アクセス時に指定。データ名は5〜259バイトの固定長項目。

⑧ NOMINAL KEY文節

構文
NOMINAL KEY IS データ名

索引付ファイル及び相対ファイルをランダム・アクセス時に指定。

⑨ RECORD KEY文節

構文
RECORD KEY IS データ名

索引ファイルをアクセスする為に使用。255バイト以下の固定長項目。

⑩ TRACK-AREA文節

構文
TRACK-AREA IS { データ名 }
              { 整数     }

索引ファイルに対しランダム・アクセス方式でレコードを追加する場合。8の倍数で32760バイト以内。

⑪ TRACK-LIMIT文節

構文
TRACK-LIMIT IS 整数 TRACK(S)

I-O-CONTROL

① RERUN文節

チェックポイント・レコードを取る事を指定する。

構文
RERUN ON システム名
  EVERY { 整数       RECORD }
        { [END OF] { REEL } }
               { UNIT       }

② SAME文節

処理中に2つ以上のファイルが同じコア記憶域を使用する事を指定。

構文
SAME [ SORT   ] AREA FOR ファイル名-1…n
     [ RECORD ]

④ APPLY文節

構文
APPLY WRITE-ONLY ON ファイル名-1…n
APPLY CORE-INDEX ON ファイル名-1…n

4DATA DIVISION（データ部）

形式

COBOL — DATA DIVISION 形式
DATA DIVISION.
FILE SECTION.
WORKING-STORAGE SECTION.
LINKAGE SECTION.
REPORT SECTION.

記入例

COBOL — DATA DIVISION 記入例
DATA           DIVISION.
FILE           SECTION.
FD INFL               RECORDING MODE IS F
                      RECORD   CONTAINS 20 CHARACTERS
                      LABEL    RECORD IS STANDARD
                      DATA     RECORD IS IN-REC.
01 IN-REC.
05 IN-KUBUN            PIC X(2).
05 IN-NAIYO.
10 IN-NAIYO-1          PIC X(5).
10 IN-NAIYO-2          PIC X(10).
10 FILLER              PIC X(20).
WORKING-STORAGE SECTION.
77 COUNTER              PIC 99.
01 IN-DATA.
05 IN-KBN               PIC X(5).
05 IN-NAIYO             PIC X(15).
LINKAGE        SECTION.
01 PARM.
05 PARM-LL              PIC 9(3) COMP.
05 PARM-YMD             PIC X(6).

FILE SECTION

プログラム中で使用される外部データのDCBなどを記述する。1つのプログラム中で25個以内のファイル記述項目を書ける。

① BLOCK CONTAINS文節

構文
BLOCK CONTAINS [整数-1 TO] { CHARACTERS }
                { RECORDS    }

物理レコードのブロック長を指定。1レコード1ブロックのデータには指定不要。

② RECORD CONTAINS文節

構文
RECORD CONTAINS [整数-1 TO]整数-2 CHARACTERS

③ RECORDING MODE文節

モード説明
F全てのレコードが同じ長さ。ブロック内のレコード数固定
U固定/可変長可。ブロックに1レコードのみ
V固定/可変長可。ブロックに1〜nレコード
S固定/可変長可。1レコードが1ブロックより大きい場合可

④ LABEL RECORD文節

構文
LABEL { RECORD IS  } { OMITTED       }
      { RECORD ARE } { STANDARD      }
             { データ名-1…n }

⑥ DATA RECORD文節

構文
DATA { RECORD IS  } データ名-1…n
     { RECORD ARE }

データ記述項目

構文
レベル番号 { データ名 } PICTURE句
           { FILLER   }

レベル番号は01〜49まで指定できる。通常01, 05, 10…の順で付けていく。

COBOL — レベル番号の例
01 IN-REC.
05 IN-KUBUN      PIC X(2).
05 IN-NAIYO.
10 IN-NAIYO-1  PIC X(5).
10 IN-NAIYO-2  PIC X(10).
10 FILLER      PIC X(20).

IN-RECという37バイトのレコード。IN-KUBUNが2バイト、IN-NAIYOの中にIN-NAIYO-1(5バイト)、IN-NAIYO-2(10バイト)。

WORKING-STORAGE SECTION

プログラム中でワークとして使用するエリア、INPUT/OUTPUTのエリアをコピー・指定するエリア、カウンターやスイッチのエリアを定義する。

特殊レベル

レベル名称説明
77独立項目下位レベルをもたない独立項目（88レベルを除く）
88条件項目エリアをもたない。上位レベルの条件を示す
66再編成項目データ項目のグループを再編成（REDEFINES関連）

88レベルの例

COBOL — 88レベル
77 FILE-SIGN            PIC X.
88 EOF-SIGN             VALUE "E".

"E"をFILE-SIGNへ移送したかどうかを確認するには、IF FILE-SIGN="E" ではなく IF EOF-SIGN と書くだけでよい。

PICTURE句

エリアの長さ・TYPEなどを指定。PICTUREはPICと省略できる。

9-TYPE

数字項目。0〜9以外を移送できない（COMPUTATIONAL）。

COBOL
PIC 9(5).   <─ 5桁数字

小数点の指定

種類記述バイト
仮想小数点PIC 999V99.5バイト（Vはエリアを取らない）
実小数点PIC 999.99.6バイト（.が1バイト確保）

サインの指定

COBOL
PIC S99.    <─ 1バイトの符号エリア

ゾーン・パック・2進数

形式例（2バイトに"11"を移送）PIC記述
ゾーンF1 F1PIC 9(2).
パック01 1CPIC S9(3) COMP-3.
2進数00 0BPIC S9(3) COMP-8.

パックの最後の4ビット: C/F=プラス、D=マイナス。
2進数のサインは最上位ビット（1=マイナス、0=プラス）。

COBOL — COMP SYNCの指定方法
① 05 CTR-IN               PIC S9(7) COMP SYNC.
② 01 CTR-AREA             COMP SYNC.
   05 CTR-IN               PIC S9(7).
   05 CTR-OUT              PIC S9(7).

②の方がクリアが楽なので通常②の使い方をすることが多い。

A-TYPE

アルファベット項目。アルファベットとブランクの27文字。ほとんど使われない（X-TYPEで代用可能）。

X-TYPE

英数字項目。COBOLで使用する全ての文字を移送可能。

編集TYPE

文字意味
Bブランク挿入
P小数点以下の桁数
−マイナス表示（符号）
＋プラス表示
¥通貨記号
ZZERO消去
＊チェック保護
V仮想小数点
0ZERO表示
，カンマ
．ピリオド
CR値が負の時にCR表示
DB値が負の時にDB表示

編集TYPE使用例

指定データの値結果
PIC 99BB99BB99.12345612△△34△△56
PIC ZZZZZZ.001234△△△1234
PIC Z,ZZZ,ZZ9.001234△△1,234
PIC −,---,--.−001234−1,234
PIC +,+,,,+,,+001234+1,234
PIC ¥,¥¥¥,¥¥¥.12345¥12,345
PIC ＊＊＊＊＊＊＊＊.12345*****12345

DB/CRの例

COBOL
PIC 9(5) DB.    <─ 負の値の場合 999DB（正なら 999）
PIC 9(5) CR.    <─ 負の値の場合 999CR（正なら 999）

VALUE文節・JUST RIGHT句・REDEFINE・OCCURS

VALUE文節

COBOL
05 A                 PIC X(11).
VALUE IS "** START **".

ISは省略可。テーブル作成時に良く使用。

JUST RIGHT句

COBOL
05 A                 PIC X(10) JUST RIGHT.

通常左詰めだが、これを右詰めにする。基本項目に対してのみ指定可能。

REDEFINE文節

一度定義したエリアを違った形で定義し直す。新たにエリアは取らない。

COBOL
05 A.                      PIC X(10).
05 A-R REDEFINES A.
10 B                       PIC 9(5).
10 C                       PIC S9(5).
10 D                       PIC X(1).

日付のREDEFINE例

COBOL
05 A-YYMMDD.
10 A-YYMM.
15 A-YY                    PIC X(2).
15 A-MM                    PIC X(2).
10 A-DD                    PIC X(2).
05 A-YYMMDD-R REDEFINES A-YYMMDD.
10 A-YY-R                  PIC 9(2).
10 A-MMDD.
15 A-MM-R                  PIC 9(2).
15 A-DD-R                  PIC 9(2).

OCCURS文節（テーブル）

構文
OCCURS 整数 TIMES
  (DEPENDING ON データ名-1)
  { ASCENDING  } KEY IS データ名-2
  { DESCENDING }
  INDEXED BY 指標名
COBOL
05 A OCCURS 30 TIMES
   INDEXED BY A-X1.
10 B                       PIC X(1).

Bというエリアが30個あり、A-X1で参照可能。B(1), B(2) または B(A-X1)。

OCCURSは最大3次元まで可能。

COBOL — 3次元テーブル
05 A   OCCURS 3  TIMES INDEXED BY A-X1.
10 B   OCCURS 5  TIMES INDEXED BY B-X1.
15 C   OCCURS 2  TIMES INDEXED BY C-X1.
20 D                        PIC X(20).

Dは3×5×2=30個、600バイト。D(1,1,1) または D(A-X1, B-X1, C-X1)。

LINKAGE SECTION

外部から渡されるデータ（パラメータ）、上位モジュールからのデータを定義。パラメータはDATAの他に長さが入るエリアを定義する必要がある。

COBOL
01 PARM.
05 PARM-LL    PIC 9(3) COMP.
05 PARM-YMD  PIC X(6).

太ったゼロとやせたゼロ

プログラム中には太ったゼロ（O）とやせたゼロ（0）がある。文法のミスはないはずなのにコンパイルが通らない。よくよく見てみると、何が問題か。

COBOL
MOVE……が MOVE……となっているではないか。

いやはや、やせたゼロ（0）が邪魔をしていたのか！ JCLでも同じミスをよくやる。コーディングの時はOと0を見分けやすいように書こう。

5PROCEDURE DIVISION（手続き部）

このDIVISIONでは実際にやる処理をCOBOLの命令を使って定義する。

主な命令一覧

ACCEPTREADCALL
ADDMOVESTOP RUN
SUBTRACTSETGOBACK
MULTIPLYPERFORMSEARCH
DIVIDEGO TOWHEN
REMAINDEROPENDISPLAY
COMPUTECLOSEAT END
IFEXAMINEBEFORE
ELSEWRITEAFTER

1. ACCEPT命令

構文
ACCEPT データ名 [FROM { SYSIN   }
                     { CONSOLE }
                     { 記憶名  }]

FROMを省略するとSYSINからの入力とみなされる。

2. ADD命令（加算）

構文 — TO形式
ADD 識別名-1…(n) TO 識別名-2…(n) [ROUNDED]

TOの左側の内容が右側に足し込まれて、右側の値が結果と置き換わる。

構文 — GIVING形式
ADD 識別名-1…(n) GIVING 識別名-2…(n) [ROUNDED]

GIVING形式では左側の加算結果が右側へストアされる（元データは保存）。

例

COBOL
05 A PIC 9(2).    ……10
05 B PIC 9(3).    ……30
05 C PIC 9(4).    ……0
ADD A B GIVING C.  <─ 結果 C=40（A,Bは保存）
ADD 1 TO IN-CTR.   <─ カウントアップ

3. SUBTRACT命令（減算）

構文
SUBTRACT 識別名-1…(n) FROM 識別名-2…(n) [ROUNDED]
SUBTRACT 識別名-1…(n) FROM 識別名-2…(n) GIVING 識別名-3 [ROUNDED]

4. MULTIPLY命令（乗算）

構文
MULTIPLY 識別名-1 BY 識別名-2 [ROUNDED]
MULTIPLY 識別名-1 BY 識別名-2 GIVING 識別名-3 [ROUNDED]

5. DIVIDE命令（除算）

構文
DIVIDE 識別名-1 INTO 識別名-2 [ROUNDED]
DIVIDE 識別名-1 INTO 識別名-2
        GIVING 識別名-3 [ROUNDED]
        [REMAINDER 識別名-4]

REMAINDERは余りを求めるオプション。INTOをBYに変えると除数と被除数の関係が逆転する。

例

COBOL
05 A PIC 9(2).      ……13
05 B PIC 9(3).      ……100
05 C PIC 9(2).
05 D PIC 9(2).
DIVIDE A INTO B GIVING C REMAINDER D.
        <─ 結果 C=7, D=9

6. COMPUTE命令

ADD/SUBTRACT/MULTIPLY/DIVIDEの機能を算術演算式で指定できる。

記号意味
＝イコール
＊乗算
／除算
＋加算
−減算
＊＊べき乗
（ ）優先度
COBOL
COMPUTE C = ((A+B) / (B-E)) * D.

受項目（＝の左側）は9-TYPEでなければならない。編集項目でも可能（PIC ZZZ. など）。

実行順序

（ ）内 → べき乗 → 乗算/除算 → 加算/減算 → 同レベルは左から順

ON SIZE ERROR

COBOL

  ON SIZE ERROR GO TO ERR-SHORI.

7. IF命令

構文
IF    条件    ステートメント-1    NEXT SENTENCE
ELSE        ステートメント-2    NEXT SENTENCE
COBOL

  PERFORM S03-EQUAL-SHORI THRU S03-EXIT
ELSE
  NEXT SENTENCE.

IF文を入れ子にすることをネスティングと呼ぶ。

8. READ命令

構文
READ ファイル名 [INTO データ名]
  AT END 命令ステートメント.

OPEN命令が実行されていなければ ABEND=U3706 となる。

9. MOVE命令

構文
MOVE 識別名-1 TO 識別名-2 (n)
MOVE ZERO TO A B C.      <─ A,B,Cをゼロクリア
MOVE A       TO B.        <─ Aの内容をBへ

インデックスには使えない（SET命令を使用）。

10. SET命令

構文
SET INDEX名 TO    識別名-1
SET INDEX名 UP BY  識別名-1
SET INDEX名 DOWN BY 識別名-1

右側のものが左側へセットされる（MOVEとは逆）。

11. PERFORM命令

構文
PERFORM 処理手順名-1 [THRU 処理手順名-2]
            [識別名-1 TIMES]

UNTILオプションで条件付き繰り返し可能。

COBOL
PERFORM S04-SHORI THRU S04-EXIT
  UNTIL SW-END = 'E'.

VARYINGオプションで複雑なテーブル処理も可能。

12. GO TO命令

構文
GO TO 処理手順名
GO TO 処理手順名-1
     処理手順名-2
     処理手順名-n DEPENDING ON 識別名

DEPENDING ONで識別名の値に応じてブランチ先が変わる。

13. OPEN命令

構文
OPEN INPUT  ファイル名-1…(n)   <─ READ専用
OPEN OUTPUT ファイル名-2…(n)   <─ WRITE専用
OPEN I-O    ファイル名-3…(n)   <─ 両方

14. CLOSE命令

構文
CLOSE ファイル名-1…(n)

15. WRITE命令

構文
WRITE レコード名 [FROM 識別名]
[BEFORE ] ADVANCING 識別名 LINES
[AFTER  ]

BEFOREとAFTERの違い:

指定動作
BEFORE 2先にプリント、そのあと2+1ライン進む
AFTER 2先に2ライン進む、プリント、さらに1ライン進む

効率はBEFOREの方が良い（プリント中に次データをセット可能）。

16. DISPLAY命令

構文
DISPLAY 識別名-1…(n) [UPON { CONSOLE  } ]
                      { SYSOUT   }
                      { SYSPUNCH }
                      { SYSPCH   }
出力先最大桁数

CONSOLE100桁
SYSPUNCH72桁

17. SEARCH命令

構文
SEARCH テーブル名 [AT END 命令ステートメント-1]
  WHEN 条件 命令ステートメント-2
COBOL
SET A-X1 TO 1.
SEARCH A-OCCUR
  AT END GO TO SEARCH-END
WHEN WK-KEY = A-KEY(A-X1)
  MOVE A-NAIYO(A-X1) TO WK-DATA.

SEARCH前に必ずインデックスに値をSETする。IF文でLOOPさせるよりステートメント数が少ない。

STOP RUN — プログラム停止（単体モジュール）
GOBACK — 制御を上位モジュールへ返す（サブモジュール）

5. コントロールブレイクのフロー例

プリントルーチン

53ラインを超えたら見出しを打つ。ライン数をカウントして53ラインを超えたら改頁して見出しを打ち、ラインカウンターを初期値化する。

ブレークキーの定義

COBOL — ブレークキーの定義
05 KEY.
10 KEY1               PIC X(3).    <─ READ時のKEY（大項目: 支社）
10 KEY2               PIC X(3).    <─ 中項目: 営業部
10 KEY3               PIC X(3).    <─ 小項目: 支部
05 STR.
10 STR1               PIC X(3).    <─ 1件前のKEY（大）
10 STR2               PIC X(3).    <─ 1件前のKEY（中）
10 STR3               PIC X(3).    <─ 1件前のKEY（小）

処理の流れ

  1. 1件目のREAD時にKEYとSTRにMOVE
  2. FILE ENDか確認 → ENDなら小計・中計・合計をプリントしてEND
  3. KEYとSTR比較 → 同じなら明細プリントして集計処理
  4. KEY1≠STR1 → 小計・中計・合計をプリント、KEY→STRへMOVE
  5. KEY2≠STR2 → 小計・中計をプリント、KEY2→STR2, KEY3→STR3へMOVE
  6. KEY3≠STR3 → 小計をプリント、KEY3→STR3へMOVE
  7. ④〜⑥終了後、明細プリント・集計処理 → ①へ戻る

7TSO

TSOの周辺のファイル、TSOでテストする場合とJCLとの違い、コマンドプロシジャーの基本的な作成方法を説明する。

TSOのLOGON

TSOコマンド
LOGON USER-ID/PASSWORD [↵]

例: LOGON @QAKOBA/1111 [↵]
このコマンドを入れるとTSO画面はREADYになり使用可能となる。

ファイル説明

ファイル説明
MASTER (MASTRLIB)最終的なソースプログラムが登録されている
SOURCE (SOURCLIB)パンチされたプログラムが入り修正・更新される。定期的にスクラッチ
PDSLIBDCOPY又はCOPY文のソースが入っている
TEST.CPYLIBTSOよりSUBCOPYされたDCOPYが一時的に入る。毎週月曜日にスクラッチ
DASD.CPYLIB完成されたDCOPYがTEST.CPYLIBよりコピーされて入る
TESTLIB1TSOよりCOMPILEされたものが入る
TESTLIB2リンクされたロードモジュールを一時的にカタログ
DASDLIB1, DASDLIB2等最終的なロードモジュールがカタログされる

ソースからロードモジュールまで

  1. コーディングを終えてパンチ → ソースリブに登録
  2. TSOから LIBC / LIBA でソースリブからTSOワーク上に持ってくる。修正後、SUBCB2W / SUBASHW でコンパイル/アセンブル → TESTLIB1へカタログ
  3. リンク処理（SUBLKEDなど）。CALL命令がなければリンク不要
  4. リンクされたモジュール → TESTLIB2へカタログ（ロードモジュール）
  5. TEST命令でテストを繰り返し、エラーがなくなるまで②〜④を繰り返す
  6. 完成したロードモジュール → DASDLIB1 / DASDLIB2 へ登録
