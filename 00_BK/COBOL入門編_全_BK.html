第一章 COBOLの概説

1. COBOLの単位

語はCOBOL予約語、あるいはプログラマーによって定義される語のいずれかである。

予約語はCOBOLコンパイラーに対し、特定の統語上意味を持っている。

プログラマーによって定義される語は、データ名やプログラム名などの項目で名前を付ける際はCOBOLの規則に従わなければならない。

2. 4つのDIVISION

各DIVISIONは論理的な順序に配置される。コーディングの順序は以下のとおりである。

IDENTIFICATION DIVISION.   （見出し部）
ENVIRONMENT    DIVISION.   （環境部）
DATA           DIVISION.   （データ部）
PROCEDURE      DIVISION.   （手続き部）
  • IDENTIFICATION DIVISION — プログラム名、プログラム作成者、作成日などを記入する。
  • ENVIRONMENT DIVISION — プログラムを処理する具体的な計算機の構成に関する情報、JCLのDD名とDCB名の対応づけなどを記入する。
  • DATA DIVISION — プログラムで扱う全てのデータの形式、性質、及び作業用エリアとして使用するエリアの定義などを記入する。
  • PROCEDURE DIVISION — 計算機に実行させたい処理をCOBOLの命令により記入する。

第二章 IDENTIFICATION DIVISION（見出し部）

1. 形式

IDENTIFICATION DIVISION.      ← 省略不可
PROGRAM-ID.  プログラム名.     ← 省略不可
AUTHOR.      プログラム作成者        ← 省略可能
DATE-COMPILED.  コンパイル日付     ← 省略可能
DATE-WRITTEN. プログラム作成日      ← 省略可能
INSTALLATION. 会社名、課名、etc   ← 省略可能
SECURITY.    情報の極秘等          ← 省略可能
REMARKS.     プログラムの概要処理    ← 省略可能

コンパイル日付は機械の方でコンパイル時に入れてくれるので、プログラマーが記入する必要はない。記入した時には機械の方の日付は無視される。

記入例

IDENTIFICATION    DIVISION.
PROGRAM-ID.  SS001601.
DATE-COMPILED.
REMARKS.     MIX DUMP.

尚、REMARKSは、項目中にスペースがあっても、2行になっても、全くプログラムに差しつかえはない。

第三章 ENVIRONMENT DIVISION（環境部）

1. 形式

ENVIRONMENT DIVISION.           ← 省略不可
CONFIGURATION SECTION.          ← 省略不可
SOURCE-COMPUTER.                ← 省略不可
OBJECT-COMPUTER.                ← 省略不可
SPECIAL-NAMES.                  ← 省略可能
INPUT-OUTPUT SECTION.           ← 省略可能
FILE-CONTROL.                   ← 省略可能
I-O-CONTROL.                    ← 省略可能

＊の4つは指定しなければならない。＊のない4つは、プログラム上あるいは、ファイルの都合上、指定せねばならないものもある。

記入例

ENVIRONMENT       DIVISION.
CONFIGURATION     SECTION.
SOURCE-COMPUTER.  IBM-370.
OBJECT-COMPUTER.  IBM-370.
SPECIAL-NAMES.    C01 IS F-FILE
INPUT-OUTPUT
FILE-CONTROL.     SECTION.
    SELECT INFL ASSIGN TO UT-S-INFL.
    SELECT OTFL ASSIGN TO UT-S-OTFL.
I-O-CONTROL.
    APPLY WRITE-ONLY ON OTFL.

(1) SPECIAL-NAMES

これは、プリントなどでファーストラインに名前を付けるものである。（C01のみ使用）

例えば、C01 IS FIRST-LINE と記入すると、チャネル01（C01）の名前を FIRST-LINE とすると定義することである。これは、PROCEDURE DIVISIONでプリントファイルにWRITEする时使用される。BEFOREもしくはAFTERで FIRST-LINE と書くと命令が実行された後、もしくは前にプリンタのポインタはTOPを指す。詳細はWRITE命令を参照。

(2) SOURCE-COMPUTER

この段落は文書化の働きしかしない。コンパイルする電子計算機について記述する。通常、IBM-9790. の様に記述する。

(3) OBJECT-COMPUTER

SOURCE-COMPUTERと同じで実行する計算機について記述する。MEMORY SIZE や SEGMENT-LIMIT などのOPTIONがあるが、ここでは省略する。

(4) INPUT-OUTPUT SECTION（コントロールセクション）

個々のファイルの定義。ファイルを入れる外部記憶媒体の識別（JCLのDDとの関連付け）、1つ又は2つ以上の入出力装置へのファイルの割り当てなどを定義するセクションで、FILE-CONTROL段落と、I-O-CONTROL段落がある。

(5) FILE-CONTROL

ファイルを入出力装置に割り当てる。

（形式）

  • SELECT 文節
  • ASSIGN 文節
  • RESERVE 文節
  • FILE-LIMIT 文節
  • ACCESS MODE 文節
  • PROCESSING MODE 文節
  • ACTUAL KEY 文節
  • NOMINAL KEY 文節
  • RECORD KEY 文節
  • TRACK-AREA 文節
  • TRACK-LIMIT 文節

① SELECT 文節

SELECT文節は、プログラム中の個々のファイルに名前を与える為に使用される。

SELECT ファイル名

このファイル名で書いた名前は、DATA DIVISION中のFD又はSD項目を持っていなければならない。

② ASSIGN 文節

ASSIGN文節は、ファイルを外部媒体（JCL上のDD名）に割り当てるものである。

ASSIGN TO システム名

システム名の構成：クラス（−装置）−編成−名前

クラス

クラス説明
DA大容量記憶装置
UTユーティリティ（IBMではほとんどUTを使用）
URユニットレコード

UT及びURに割り当てられるファイルは標準順次編成でなければならない。DAは順次編成又は直接編成のいずれでもよい。

装置 — 通常指定しない。

UT…2301, 2302, 2303, 2311, 2321, 2314 など
UR…1403, 1404, 1443 など

編成 — 1文字のフィールドで示す。

編成説明
S標準順次編成
D直接編成
WREWRITE使用時の直接編成
R相対編成
I索引編成

名前 — 1〜8文字までで示すDD名である。

③ RESERVE 文節

コンパイラーが割り当てられる入出力域（BUFF）の数をユーザーが修正できる様にするものである。

RESERVE { NO        } ALTERNATE [ AREA  ]
         { 整数     }            [ AREAS ]

整数で示される偶数だけBUFFが確保される。但し、順次アクセスにのみ有効。

④ FILE-LIMIT 文節

この文節は、コメントとして扱われるので省略する。

FILE-LIMIT IS リテラル-1 THRU リテラル-2

⑤ ACCESS MODE 文節

ファイルのレコードをアクセスする方法を規定する。

ACCESS MODE IS { SEQUENTIAL }
               { RANDOM     }

省略時は、SEQUENTIALとみなされる。

⑥ PROCESSING MODE 文節

この文節は、指定してもコメントとして扱われる。

PROCESSING MODE IS SEQUENTIAL

⑦ ACTUAL KEY 文節

ランダム・アクセスの時には、指定しなければならない。

ACTUAL KEY IS データ名

データ名は、5〜259バイトの長さの固定長項目であり、DATA DIVISIONで指定しなければならない。

⑧ NOMINAL KEY 文節

索引付ファイル及び相対ファイルをランダム・アクセスする時、指定しなければならない。

NOMINAL KEY IS データ名

データ名は、1〜255バイトの長さの固定長のWORKING-STORAGE SECTIONで項目を指定することができる。

⑨ RECORD KEY 文節

索引ファイルをアクセスする為に使用する。

RECORD KEY IS データ名

データ名は、255バイト以下の固定長項目でなければならない。

⑩ TRACK-AREA 文節

索引ファイルに対し、ランダム・アクセス方式でレコードを追加する場合、使用される。この文節を使用するとレコード追加の効率よくなる。

TRACK-AREA IS { データ名 }
               { 整数    }

定義される区域は、8の倍数で、32760バイト以内。

⑪ TRACK-LIMIT 文節

直接編成ファイルの作成時、初期値化すべき最後のトラックの相対番号を示すものである。

TRACK-LIMIT IS 整数 TRACK(S)

(6) I-O-CONTROL

（形式）

I-O-CONTROL.
  RERUN 文節
  SAME AREA 文節
  MULTIPLE FILE TAPE 文節
  APPLY 文節

① RERUN 文節

RERUN文節は、チェックポイント・レコードを取る事を指定するものである。

RERUN ON システム名
EVERY { 整数           RECORD }
      { [END OF] { REEL }     }
              { UNIT }       }
  • システム名は、チェックポイント・レコードが書かれるファイル。
  • ファイル名は、チェックポイント・レコードをどのファイルの為に取るのか、その目的のファイルを表す。これはDATA部で定義されていなければならない。

② SAME 文節

処理中に2つ以上のファイルが同じコア記憶域を使用することを指定する。

SAME [ SORT   ] AREA FOR ファイル名-1…n
     [ RECORD ]

③ MULTIPLE FILE TAPE 文節

これは文書化の為に使用される。

MULTIPLE FILE TAPE CONTAINS ファイル名-1
POSITION 整数-1…n

④ APPLY 文節

(I) APPLY WRITE-ONLY ON ファイル名-1…n
これは、Vモードのレコードをもつファイルをアウトファイルに対し使用する。この指定をした時のWRITE文は、WRITE レコード名 FROM エリア名 の形をとらなければならない。指定しないと、ブロッキングの使用効率が非常に悪くなる。

(II) APPLY CORE-INDEX ON ファイル名-1…n
これは、ランダム・アクセスの索引付ファイルに対してのみ指定できる。

第四章 DATA DIVISION（データ部）

1. 形式

DATA DIVISION.
FILE SECTION.
WORKING-STORAGE SECTION.
LINKAGE SECTION.
REPORT SECTION.

記入例

DATA              DIVISION.
FILE              SECTION.
FD INFL     RECORDING MODE IS F
    RECORD  CONTAINS 20 CHARACTERS
    LABEL   RECORD IS STANDARD
    DATA    RECORD IS IN-REC.
01 IN-REC               PIC X(20).
WORKING-STORAGE SECTION.
77 COUNTER              PIC 99.
01 IN-DATA.
    05 IN-KBN            PIC X(5).
    05 IN-NAIYO          PIC X(15).
LINKAGE       SECTION.
01 PARM.
    05 PARM-LL           PIC 9(3) COMP.
    05 PARM-YMD          PIC X(6).

(1) FILE SECTION

ここでは、プログラム中で使用される外部データのDCBなどを記述する。

FILE SECTION.
{ファイル記述項目}
{レコード記述項目}

A. ファイル記述項目

FD ファイル名
  BLOCK CONTAINS 文節
  RECORD CONTAINS 文節
  RECORDING MODE 文節
  LABEL RECORD 文節
  VALUE OF 文節
  DATA RECORD 文節
  REPORT 文節

1つのプログラム中で25個以内のファイル記述項目を書く事ができる。

① BLOCK CONTAINS 文節

ここでは、物理レコードのブロック長を指定する。

BLOCK CONTAINS [整数-1 TO] { CHARACTERS }
                [整数-2  ] { RECORDS    }

1レコード1ブロックのデータには、この文節を指定する必要はない。データがFIXの時は、整数-2だけを指定する。データがVARIABLEの時は、整数-2はMAXのレコード長を指定し、整数-1を指定する時は、MINのレコード長を記入する。例えば、BLOCK CONTAINS 1 TO 3 RECORDS と指定すると、最小1レコード最大3レコードであることを意味している。

② RECORD CONTAINS 文節

ここでは、データ・レコードの大きさを指定する。

RECORD CONTAINS [整数-1 TO] 整数-2 CHARACTERS

通常、整数-2を指定する。整数-2はMAXのレコードの大きさ。整数-1を指定する時は、データがVARIABLEの時で、レコードの最小値を指定する。記入例はBLOCK CONTAINS文節と同じである。

③ RECORDING MODE 文節

ここでは、F, U, V, Sを指定することができる。

RECORDING MODE IS モード
モード説明
Fファイル内、全てのレコードが同じ長さ。通常各ブロックに入るレコード数は固定。
Uレコードの長さは固定/可変どちらでもよい。ただし各ブロックには1レコードしか入らない。
Vレコードの長さは固定/可変どちらでもよいが、それぞれ1つのブロックの中に1〜n個のレコードは収まっているなければならない。
Sレコードの長さは固定/可変どちらでもよく、1レコードが1ブロックより大きくてもよい。

U, Vモードは索引付編成、および相対編成のファイルには指定できない。Sモードは、標準順次ファイル、又は直接ファイルに対して指定できる。

④ LABEL RECORD 文節

ここでは、ラベルの有無を指定するものである。

LABEL { RECORD IS  } { OMITTED   }
      { RECORD ARE } { STANDARD  }
                  { データ名-1…n }
  • OMITTED — ユニット・レコード装置に割り当てられているファイルに対して必ず指定しなければならない。（ただしIBMではSTANDARDで処理可能）
  • STANDARD — ファイルに数個のラベルがついており、システム仕様に従っていることを指定。索引付編成はSTANDARDを指定しなければならない。
  • データ名-1…n — ユーザーラベルで標準外ラベル。

⑤ VALUE OF 文節

この文節は、コメントとして扱われるので指定する必要はない。

VALUE OF データ名-1 IS { データ名-2  }
                       { リテラル-1  }

⑥ DATA RECORD 文節

FD文の後で書くデータレコードの名前を指定する。

DATA { RECORD IS  } データ名-1…n
     { RECORD ARE }

データ名を複数指定する時は、01レベルでその分をとらなければならない。

(2) データ記述項目

データ記述項目は、後で述べるWORKING-STORAGE SECTIONで説明することと重なる部分が多いが、基本的な記述形式を示す。

レベル番号 { データ名 } PICTURE句
           { FILLER  }

レベル番号は、データの内容にレベル付けをするもので 01〜49 まで指定できる。通常、01, 05, 10… の順で付けていく事が多い。

ファイルの項目のDATA RECORD文節で指定したDATA名をここで01レベルで定義しなければならない。

定義例

DATA RECORD IS IN-REC と定義済み
01 IN-REC.
    05 IN-KUBUN       PIC X(2).
    05 IN-NAIYO.
        10 IN-NAIYO-1 PIC X(5).
        10 IN-NAIYO-2 PIC X(10).
        10 FILLER     PIC X(20).

これは、IN-RECという名前のレコードがあり、37バイトであることを示している。その内訳は、IN-KUBUNという名前のエリアが2バイトでIN-NAIYOというエリアの中にIN-NAIYO-1というエリアが5バイトでIN-NAIYO-2というエリアが10バイトあるという事である。FILLER 20バイト。

PICTURE句及びその他の事は後で述べる。通常は、レコード名を01レベルでとり、PICTURE句を付け、内訳は書かない。実際の内訳は、WORKING-STORAGE SECTIONで記述する形が多く使用されている。

① WORKING-STORAGE SECTION

ここでは、プログラム中でワークとして使用するエリア、INPUTやOUTPUTのエリアをコピーしたり指定したりするエリア、カウンターやスイッチのエリアを定義するエリアである。

記述の方法は、データ記述項目と同じであるがレベルに特別な物がある。66, 77, 88 である。77レベルは、記述する時は、このセクションの最初で定義しなければならない。

ア. 77レベル（独立項目）

このレベルは、下位レベルをもたない。故に独立項目と呼ばれる（ただし88レベルを除く）。

イ. 88レベル（条件項目）

このレベルの項目はエリアをもたない。上位レベルでエリアを定義し、88レベルでその条件を示す。

ウ. 66レベル（再編成項目）

このレベルの項目は、データ項目のグループを再編成する項目であるがここでは説明を除く。

88レベルの例

77 FILE-SIGN PIC X.
   88 EOF-SIGN VALUE "E".

上記の様に定義して、"E"という文字をFILE-SIGNへ移送する。通常このエリアに"E"が入ったかどうかを聞く為には IF FILE-SIGN = "E" と記述するが88レベルを記述している為、IF EOF-SIGN と書くだけでよい。= "E" と書く必要がない。なぜなら、VALUE "E" と定義している為、PIC Xのエリアに"E"という文字が入った時だけ条件が満たされる。これは各自で実際にやってみると納得できる。

PICTUREのTYPEには、9-TYPE, A-TYPE, X-TYPE、及び編集TYPEがある。

ア. 9-TYPE

PIC 99. の様に指定する。尚、長さを（）で囲んで指定する事ができる。例: PIC 9(2). これはどのTYPEでも同じである。このエリアは数字項目であり、0〜9以外の文字を移送することはできない。（COMPUTATIONAL / 計算のみ）

イ. A-TYPE

PIC AA. の様に指定する。このエリアはアルファベット項目である。このエリアに移送できるデータは、アルファベットとブランクの27文字のデータである。この項目はほとんど使われない。次に説明するX-TYPEで代用できるからである。

ウ. X-TYPE

PIC XX. の様に指定する。このエリアは英数字項目である。このエリアにはCOBOLで使用できる全ての文字を移送できる。したがって通常、数字が入っているがその他の文字が時折入ってくるとか、FILLERで定義されるエリアをX-TYPEで定義する。

尚、グループ項目（PIC句をもたないレベル項目）は、全てX-TYPEとして扱われる。

01 IN-REC.
    05 IN-1   PIC S9(3) COMP-3.
    05 IN-2   PIC A(3).
    05 IN-3   PIC X(5).

上記の様なエリアが定義されている時、MOVE SPACE TO IN-1 という命令は使えないが、MOVE SPACE TO IN-REC という命令は使える。しかし、SPACEを送ったあと、IN-1というエリアを使用すると、ABEND OC7（データエラー）となる。

③ VALUE 文節

使用方法は:

④ JUST RIGHT 句

通常、X-TYPE, A-TYPEで定義されているエリア内にデータを移送する時、移送するデータが小さければ左詰めで処理される。これを右詰めで処理させようというのがこの定義である。

05 A PIC X(10) JUST RIGHT.

処理:

PIC X(8).              データ → A B C | | |
PIC X(8) JUST RIGHT.           →       | | | A B C

この項目は基本項目に対してだけ指定する事ができる。

⑤ REDEFINE 文節

この文節は、一度定義したエリアに対して違った形で定義し直すものであり、新たにエリアは取れない。あくまでも同じエリアである。

定義方法

05 A          PIC X(10).
05 A-R REDEFINES A.
    10 B      PIC 9(5).
    10 C      PIC S9(5).
    10 D      PIC X(1).
05 A-RR REDEFINES A.
    10 E      PIC X(3).

上記の様に何度でも再定義してかまわない。再定義するバイト数が再定義されるエリアのバイト数よりも大きくする事は出来ないが、小さい分には構わない。上述の例では、エリアを使用する時にA, B, Cなど、どれを参照するかによって、エリアのもつTYPEが決定される。このREDEFINES文節は日付によく使われる。

日付処理の例

05 A-YYMMDD.
    10 A-YYMM.
        15 A-YY       PIC X(2).
        15 A-MM       PIC X(2).
    10 A-DD           PIC X(2).
05 A-YYMMDD-R REDEFINES A-YYMMDD.
    10 A-YY-R         PIC 9(2).
    10 A-MMDD.
        15 A-MM-R     PIC 9(2).
        15 A-DD-R     PIC 9(2).

上記の様に指定すると同じエリアをX-TYPEでも9-TYPEでも使用できる。（YYMMDD = 年月日）

⑥ OCCURS 文節（テーブル）

この文節は反復するデータを定義するものである。

OCCURS 整数 TIMES
 (DEPENDING ON データ名-1)
 { ASCENDING  } KEY IS データ名-2
 { DESCENDING }
INDEXED BY 指標名

例1

05 A OCCURS 30 TIMES INDEXED BY A-X1.
    10 B (3バイト)  PIC X(1).

これは、Bというエリアが30個あり、A-X1というインデックスで参照できることを示している。実際にBのエリアを参照する時は、B(1) B(2) あるいは B(A-X1) という様な使い方をする。

例2

05 A OCCURS 30 TIMES
   ASCENDING KEY IS A-KEY
   INDEXED BY A-X1.
    10 A-KEY   PIC X(3).
    10 A-NAIYO PIC X(10).

これは、A-KEYというのがエリアの1番目から30番目まで、昇順であると定義している。これはSEARCHという命令に関連してくる。

DEPENDING ONは、この句を指定しないとテーブルの長さがわからない時に指定する。VBデータなどの指定時には必要である。

例3（3次元テーブル）

05 A OCCURS 3 TIMES INDEXED BY A-X1.
    10 B OCCURS 5 TIMES INDEXED BY B-X1.
        15 C OCCURS 2 TIMES INDEXED BY C-X1.
            20 D   PIC X(20).

これは、Dという20バイトのエリアが、3×5×2 = 30個、600バイトのエリアがとられる。Dを参照するには、D(1,1,1) または D(A-X1,B-X1,C-X1) の様に参照する。

この様なテーブルは、VALUE句をもっているエリアをREDEFINEしてテーブルにしたり、集計用のエリアとして定義する事が多い。

例4

05 A      PIC X(10) VALUE "ABCDEFGHIJ".
05 A-R REDEFINES A.
    10 B OCCURS 10 TIMES INDEXED BY B-X1.
        15 C   PIC X(1).

この様に定義すると、B-X1の値を変える事により、Aの中の任意の1文字を参照できる。例えば、C(3) は "C" であり、B-X1に5をSETしてやれば、C(B-X1) は "E" である。

1. ACCEPT 命令

ACCEPT データ名 [FROM { SYSIN   }
                    { CONSOLE }
                    { 記憶名  }]

データ名は、WORKING-STORAGE SECTIONで定義済みのエリア。FROMを書かないと、省略時解釈でSYSINからの入力とみなされる。この命令が行われると、SYSINもしくはCONSOLEから入力されたデータがデータ名で定義されているエリアへ格納される。

05 A PIC X(5).   ← ABCDE（カード）
ACCEPT A.         ← //SYSIN DD *
この命令で、Aというエリアには"ABCDE"と入る。

2. ADD 命令（加算）

ア. ADD 〜 TO

ADD 識別名-1…(n) TO 識別名-2…(n) [ROUNDED]

この命令は、TOの左側に書いたエリアの内容が右側に書いたエリアの内容に足し込まれて、右側のエリアの値が結果と置き換わる。ROUNDEDは四捨五入のオプションである。

05 A PIC 9(3)V9(4).   … 83.235
05 B PIC 9(4)V9(2).   … 11.46

ADD A B TO (B) ROUNDED.
→ 結果 B = 106.（小数第3位四捨五入）

イ. ADD 〜 GIVING

ADD 識別名-1…(n) GIVING 識別名-2…(n) [ROUNDED]

この形式を使うと、GIVINGの左側のエリアの内容がすべて加算されて、右側のエリアへストアされる。

05 A PIC 9(2).   … 10
05 B PIC 9(3).   … 30
05 C PIC 9(4).   … 0

ADD A B GIVING C.
→ 結果 C = 40（A, B は保存）

ADD A,B GIVING B. と ADD A TO B. — 同じ結果が得られる。

ADD A B C TO D E F.

この命令を行うと、A+B+CがD, E, Fにそれぞれ加算される。

ADD 1 TO IN-CTR. — インプット件数、ライン数をカウントする時にこの形式を使う。

3. SUBTRACT 命令（減算）

ア. SUBTRACT 〜 FROM

SUBTRACT 識別名-1…(n) FROM 識別名-2…(n) [ROUNDED]

この命令は、FROMの左側に書いたエリアの内容を全部加算して、右側のエリアの値から減算し、右側のエリアの内容が結果と置き換わる。

05 A PIC 9(2).   … 10
05 B PIC 9(3).   … 15
05 C PIC 9(4).   … 100

SUBTRACT A B FROM C.
→ 結果 C = 75（A, B は保存される）

イ. SUBTRACT 〜 FROM 〜 GIVING

SUBTRACT 識別名-1…(n) 識別名-2…(n) GIVING 識別名-3 [ROUNDED]

この形式を使うと、FROMの左側のエリアの内容を全て加算して右側のエリアから減算して結果がGIVINGで指定しているエリアへストアされる。

05 A PIC 9(2)V9(2).   … 10.01
05 B PIC 9(3)V9(2).   … 33.25
05 C PIC 9(4)V9(1).   … 100.0

SUBTRACT A FROM B GIVING C ROUNDED.
→ 結果 C = 23.2（小数第2位四捨五入で値は置き換わる）

通常、ADDもSUBTRACT命令も、GIVINGオプションを使う様な時は、便利なCOMPUTE命令を使用する事が多い。

4. MULTIPLY 命令（乗算）

ア. MULTIPLY 〜 BY

MULTIPLY 識別名-1 BY 識別名-2 [ROUNDED]

この命令はBYの左側のエリアの内容が右側のエリアに乗算されて結果が置き換わる。

05 A PIC 9(2)V9(1).   … 3.1
05 B PIC 9(3)V9(1).   … 24.1

MULTIPLY A BY B ROUNDED.
→ 結果 B = 74.7（小数第2位四捨五入）

イ. MULTIPLY 〜 BY 〜 GIVING

MULTIPLY 識別名-1 BY 識別名-2
         GIVING 識別名-3 [ROUNDED]

この形式を用いるとADDやSUBTRACTと同様に結果はGIVINGの後に指定したエリアへストアされ、乗数・被乗数共に保存される。

05 A PIC 9(2).   … 10
05 B PIC 9(2).   … 22
05 C PIC 9(4).   … 0

MULTIPLY A BY B GIVING C.
→ 結果 C = 220（A, B は保存）
05 A PIC 9(2).   … 10
05 B PIC 9(2).   … 22
05 C PIC Z(4).

MULTIPLY A BY B GIVING C.
→ 結果 C = △220（GIVINGのエリアは数字編集項目でもよい）

5. DIVIDE 命令（除算）

ア. DIVIDE 〜 INTO

DIVIDE 識別名-1 INTO 識別名-2 [ROUNDED]

この命令は、INTOの右側のエリアの内容が左側のエリアの内容で除算され、右側のエリアの内容の値が結果と置き換わる。

05 A PIC 9(2)V9(1).   … 2.9
05 B PIC 9(3)V9(2).   … 32.28

DIVIDE A INTO B ROUNDED.
→ 結果 B = 11.13（小数第3位四捨五入）

イ. DIVIDE 〜 INTO 〜 GIVING 〜 REMAINDER

DIVIDE 識別名-1 INTO 識別名-2
       GIVING 識別名-3 [ROUNDED]
       [REMAINDER 識別名-4]

この形式のREMAINDERというのは余りを求めるオプションである。INTOの左側のエリアの値で右側のエリアの値を除算し、結果をGIVING句のエリアへストアし、REMAINDER句のエリアへ余りをストアする。

05 A PIC 9(2).   … 13
05 B PIC 9(3).   … 100
05 C PIC 9(2).
05 D PIC 9(2).

DIVIDE A INTO B GIVING C REMAINDER D.
→ 結果 C = 7,  D = 9

ウ. INTO → BY

イの形式中のINTOをBYに変えると除数と被除数の関係が逆転する。この時気をつけなければいけないのは、除数・被除数のどちらかにリテラルで用いる場合である。

6. COMPUTE 命令

この命令は、前述したADD, SUBTRACT, MULTIPLY, DIVIDEなどの機能を算術文を用いて指定できる。

COMPUTE 識別名-1 [ROUNDED] = 算術演算式

記号

記号意味
=イコール
+加算
−減算
*乗算
/除算
**べき乗
()優先度

C = (A − B×D) / E という式をCOMPUTEと他の命令を使ってコーディングした場合の違いを見てみよう。

COMPUTEでは C = ((A - (B * D)) / E) というふうになる。したがって通常使用している算術文がほぼ同じ形で書ける事がわかるだろう。

ただし、COMPUTE命令には余りを求めるオプションはない。余りを必要とする時にはDIVIDE命令を使用しなければならない。

簡単な使用例

COMPUTE A = 20.

上記の様な指定をすると MOVE 20 TO A. と指定した時と同じ結果が得られる。ただしCOMPUTE命令はこのAのエリアは9-TYPEでなければならない。尚、受け項目（=の左側）は数字編集項目であってもかまわない（PIC ZZZ. など）。

命令の実行順序は、（）で囲まれている部分がまず実行され、次にべき乗、次に乗算又は除算、次に加算又は減算の順で、同レベルの場合は左から順に処理される。

式比較

A = B×C×D⁶ + 6 − E

・COMPUTE:    A = B * C * D ** 6 + 6 - E.
・伝統的:     MULTIPLY D BY D GIVING A.
              MULTIPLY D BY A.  ―――（4回繰り返す）
              MULTIPLY B BY A.
              MULTIPLY C BY A.
              ADD 6 TO A.
              SUBTRACT E FROM A.

ここで分かる様に複雑な計算式にはCOMPUTE命令の方が便利である。又、他の命令を組み合わせると全体の式がイメージしにくいという欠点もある。この様な事を考えてプログラムを組んでもらいたい。

ON SIZE ERROR

COMPUTE, ADD, SUBTRACT, MULTIPLY, DIVIDE命令には、受け項目のサイズが小さくてオーバーフローした場合のオプションがある。ON SIZE ERROR と指定するとサイズエラーの時に命令を実行する。

MULTIPLY A BY B
   ON SIZE ERROR GO TO ERR-SHORI.

この命令で、BのエリアがオーバーフローしたらERR-SHORIというルーチンへ飛んでいってその時の処理を行う。

7. IF 命令

IF文は、条件によってそれまでの処理を変える事ができる。

基本形式

IF 条件 ステートメント-1 NEXT SENTENCE
ELSE ステートメント-2 NEXT SENTENCE

条件が真であればステートメント-1が実行され、偽であればステートメント-2が実行される。

IF A = B
   PERFORM S03-EQUAL-SHORI THRU S03-EXIT
ELSE
   NEXT SENTENCE.

これは、AというエリアとBというエリアの内容がEQUALならば、S03-EQUAL-SHORIという段落名からS03-EXITという段落名までの処理を行ってから次の命令に移る。EQUALでなければ何もしないで次の命令に移る。この時のELSE NEXT SENTENCE.は省略できるが、IFとELSEは対にした方が分かり易いので書いておく方が望ましい。

尚、IF文の中にまたIF文があるという様な形を入れ子方式とかネスティングと呼ぶ。

IF A = B
   IF B NOT = C         → ネスティング
      IF C = D
         命令
      ELSE

8. READ 命令

この命令はファイルを実際にプログラム内に読込んでくる命令である。このREAD命令を実行する前に、ファイルに対してOPEN命令が実行されていなければならない。実行されていないと、ABEND=U3706などどプログラムは異常終了する。

READ ファイル名 [INTO データ名]
   AT END 命令ステートメント.
READ INFL1 INTO IN-DATA
   AT END
       MOVE '1' TO SW-EOF
       GO TO READ-END.

この命令では、INFL1が読まれ1件のデータがWORKING-STORAGE SECTIONで定義してあるIN-DATAというエリアへ入れられる。尚、ファイルがエンドの場合は、SW-EOFに'1'をたて、READ-ENDという段落名の所へ飛んでいく。

INTOを使わないと、FILE SECTIONで定義した01レベルのエリア内にデータは読み込まれている。もちろん、INTOを使っても、このエリアにはデータは入っている。すなわちINTOオプションは、READ〜MOVEに相当する。

9. MOVE 命令

この命令は記憶域のある区域から1つ又は2つ以上の区域へデータを移す為に用いられる。

MOVE 識別名-1 TO 識別名-2 (n)

MOVE ZERO TO A B C.   ← A, B, C がゼロクリア
MOVE A TO B.          ← A の内容が B へ

尚、MOVEステートメントは、インデックスには使えない。インデックスには、後述のSET命令を使う。

10. SET 命令

この命令は、インデックスに値をセットしたり、加算・減算をするものである。

SET INDEX名 TO 識別名-1
SET INDEX名  UP BY 識別名-1
SET INDEX名  DOWN BY 識別名-1

この命令では、MOVEと違い、右側のものが左側へセットされる。

SET IDX1 TO 1.        ← IDX1 というインデックスに1がセットされる。
SET IDX1 UP BY 1.     ← IDX1 が +1 される。
SET IDX1 DOWN BY 3.   ← IDX1 が -3 される。

11. PERFORM 命令

COBOLのプログラムを組む上で、処理別にセグメント化すると見やすくなるだけでなく、修正・デバッグも容易になる。このセグメント化した処理を連結する時にPERFORM命令を使用する。

基本形式

PERFORM 処理手順名-1 [THRU 処理手順名-2]
                   [識別名-1 TIMES]

これは、処理手順名-1から、処理手順名-2までを識別名-1回繰り返す、という意味である。処理手順名-2を指定していないと、次の処理手順名が出てくるまでの処理を行なう。

S03-EXIT.       ← 行ってから、PERFORM命令の次を実行。
   EXIT.

   GO TO SO5-SUB

   EXIT.          ※ 望ましくない

VARYING

条件付PERFORM命令を述べたが、もっと複雑な処理もできる。ある値をアップしながら条件を1〜3個、調べて全ての条件を満たすまでPERFORM命令が繰り返されるというものである。

この命令を使う時、ある処理を件数でブレイクしたり、年令でブレイクしたり、あるいはテーブルで持っているデータのブレイクをしたりする時に非常に便利である。一般にはテーブルの時に集計したりする時などによく使われる。

PERFORM 処理手順名-1 THRU 処理手順名-2
   VARYING 指標名-1 FROM 指標名-2 UNTIL 条件-1
   BY 指標名-3
   [AFTER 指標名-4 FROM 指標名-5
   BY 指標名-6 UNTIL 条件-2
   [AFTER 指標名-7 FROM 指標名-8
   BY 識別名-9 UNTIL 条件-3 ]]

VARYINGの例

PERFORM S05-SHORI THRU S05-EXIT
   VARYING IDX1 FROM 1
   BY 10 UNTIL A > B
   AFTER IDX2 FROM 1
   BY 10 UNTIL B > C.

ここで、IDX1, IDX2のテーブルのインデックスで、2次元のエリアを考えてもらいたい。

  1. IDX1とIDX2が1にSETされている。
  2. 条件 A > B が調べられ、真ならばこの命令の次のステートメントへ移る。
  3. 偽ならば、条件 B > C が調べられ、IDX2は1にSETされ、IDX1が1UPされる。
  4. IDX1が10を超えたら、次のステートメントへ移る。
  5. 超えていなければ、②から④が繰り返される。
  6. 条件 B > C が偽ならば、PERFORMのS05-SHORIからS05-EXITが1回実行される。
  7. IDX2の値が1UPされ、又条件 B > C が調べられる。
  8. 以上の処理が繰り返される。

この様な事から、テーブル処理に向いているといえる。

13. OPEN 命令

この命令は、ファイルをREADあるいはWRITE出来るようにあらかじめ開いておくという命令であり、READ, WRITEの前に実行しておかなければならない。尚、1度OPENするとCLOSE命令を実行するまではOPEN命令は実行できない。

通常、プログラム中では頭で（INITIAL処理で）行なう事が多い。

OPEN INPUT  ファイル名-1…(n)   ← READ専用
OPEN OUTPUT ファイル名-2…(n)   ← WRITE専用
OPEN I-O    ファイル名-3…(n)   ← 両方

ファイルをどのような使用の為に開くかという指定でINPUT（READだけ）、OUTPUT（WRITEだけ）、I-O（両方）というのを指定しなければならない。I-OでREAD/WRITEをする時はインプットとして読まれたデータに書いていくので、インプットデータは残らない。この点に気を付けて欲しい。

14. CLOSE 命令

この命令は、既に開かれているファイルを閉じる命令である。この命令を実行する前には必ずOPEN命令が実行されていなければならない。

CLOSE ファイル名-1…(n)

CLOSE INFL OUTFL   ← INFL, OUTFL を閉じる

CLOSE命令には、INPUT, OUTPUTなどの指定はいらない。尚、CLOSE命令を実行した後、FILEのREADあるいはWRITEを行う時にはOPEN命令を実行しなければならない。

このCLOSE命令において、リワインドさせるとかさせないとか、オプションがいくつかあるが、ここでは省略する。

15. WRITE 命令

この命令は、OUTPUTもしくはI-Oで開かれたファイルへ書き出しを行う命令である。

リスト以外のファイル

WRITE レコード名 [FROM 識別名]

通常のファイルに書き出す時のWRITE命令で、FILE SECTIONの01レベルで指定した名前（レコード名）の内容を書き出すという命令である。FROMを使うと、識別名の内容がレコード名へMOVEされてからWRITEする。すなわち、READ〜INTOと同じ考え方である（MOVE+WRITE）。

FILE SECTION.
FD OUTFL
01 OUTREC PIC X(100)

WORKING-STORAGE SECTION.
01 OUT-DATA.
   05 OUT-KEY

PROCEDURE DIVISION.
WRITE OUTREC FROM OUT-DATA.

この命令は、以下の2行と同じ意味である：

MOVE OUT-DATA TO OUTREC.
WRITE OUTREC.

OUT-DATAの内容をOUTREC（バッファ内）に移して書き出す。

リストへのWRITE

リストにWRITEする方法は大きく分けて2種類の方法がある。1つは1ラインプリントした後で改行を行う（BEFORE）方法、もう1つは改行を行った後プリント（AFTER）する方法である。

WRITE レコード名 [FROM 識別名]
[BEFORE  ] ADVANCING 識別名 LINES
[AFTER   ]

ここで通常ADVANCINGとLINESという語は省略して使う。この命令は、識別名の中に入っている数の分だけラインを飛ばすという事であり、ここにSPECIAL-NAMESの所で指定した C01 IS 〜 の名前を使うと、改頁されてプリントできる行の最初の行を指す。

BEFOREとAFTERの違いを見てみよう。

① WRITE PR-REC BEFORE 2

Pは現在プリンタが指しているポイント。この命令を実行すると、PR-RECの内容が現在のライン（A）へ書き出される。そして書き出したラインを含め、2+1ライン先のラインをプリンタはポイントする。すなわちCのラインにポインタは止まる。

② WRITE PR-REC AFTER 2

この命令を実行すると、まずPは2ライン先へ移る（B）。それからPR-RECの内容を書き出し、ポインタはCを指して止まる。上の2つの命令でやる場合、①の方はAのラインにプリントされ、②の方はCのラインにプリントされる。ポインタはどちらもCで止まる。

効率: BEFOREの方が良い。なぜなら、プリントしてプリンタが改行している間に、プログラムでは次にプリントする内容をセットできるからである。

1つのプログラム中では、どちらかに統一した方が、間違いが少なくて良い。

17. SEARCH 命令

この命令は、テーブルのキーを調べる命令であり、テーブルのキーを探し出し一致の時に処理を行うという命令である。テーブルにキーのデータがある場合、この命令を使わないと、IF文をループで書く必要があり、その場合、ステートメント数が必要以上に多くなる。

SEARCH テーブル名 [AT END 命令ステートメント-1]
    WHEN 条件  命令ステートメント-2
05 A-OCCUR OCCURS 100 TIMES INDEXED BY A-X1.
    10 A-KEY   PIC X(3).
    10 A-NAIYO PIC X(25).
05 WK-KEY  PIC X(3).
05 WK-DATA PIC X(25).

SET A-X1 TO 1.            ← SEARCHを実行する前には必ずインデックスをセット
SEARCH A-OCCUR            ← 必ずA-X1を1にする。
    AT END GO TO SEARCH-END
    WHEN WK-KEY = A-KEY(A-X1)
        MOVE A-NAIYO(A-X1) TO WK-DATA.

上記の様な指定で、テーブルA-OCCURのキーのデータとWK-KEYのデータとを比較している。一致したら、A-NAIYOのデータをWK-DATAへCOPYする。尚、一致しない場合は、A-X1の値が自動的にインクリメントされ、又A-OCCURのキーとWK-KEYとの比較を100回繰り返す。その間一致しなかった場合、SEARCH-ENDの所に飛んでいく。

5. コントロールブレイク

コントロール・ブレイクはファイルのKEYが変化する毎に異なる処理を行う。例えば、明細を出しながら支社・営業部・支部のトータルを出力する処理などが該当する。この処理は、通常1つのファイルを読み込んでキーによって集計する処理である。

ステップ①〜⑦の処理フロー

  1. STEP 1: ファイルをREADする。
  2. STEP 2: エンドか調べ、ENDであればSTEP6へ飛ぶ。
  3. STEP 3: ENDでなければ、STRというエリアとKEYというエリアを比較する。KEYとSTRは、ワークエリアで定義されており、ファイルにREADしたキーの1件前のキーをSTRにコピーしておいたものである。そしてKEYとSTRを比較する。
  4. STEP 4: KEYとSTRが同値であれば、STEP5へ飛ぶ。KEYとSTRが同値ではない場合、次にキーによって比較する。
  5. STEP 5: KEYとSTRが等値の場合、このキーで集計しSTEP1へ戻る。KEYとSTRが異値の場合、キーによって集計する。
  6. STEP 6: キーが異値の場合、そのキーをSTRにコピーし、集計データをゼロクリアする。
  7. STEP 7: エンドの場合、最後の集計を行い、出力してプログラム終了。

ブレークキーの定義

通常は、KEYとSTRでエリアをとっておき、キーが変化した時点で、KEYの値をSTRへCOPYする。尚、キーは複数持つ場合もあるので、キーによってエリアを分けてとっておく。尚、キーを3レベルに分けるとすれば大項目・中項目・小項目と表せる。

3. ソースからロードモジュールまで

  1. コーディングを終えてパンチ → SOURCE LIBに登録
  2. TSOから LIBC / LIBA でTSOワーク上に持ってくる。修正後 SUBCB2W / SUBASHW でコンパイル/アセンブル → TESTLIB1へカタログ
  3. リンク処理（SUBLKED など）。CALL命令がない場合はリンク不要
  4. リンクされたモジュールがTESTLIB2へカタログ（ロードモジュール）
  5. TEST 命令でテストを繰り返し、エラーが無くなるまで②〜④を繰り返す
  6. 完成したロードモジュールが DASDLIB1 / DASDLIB2 などに登録

4. JCLとTSOのテスト

JCLの例

//SAMPLE    JOB NSD,MSGLEVEL=1
//JOBLIB    DD  DSN=TESTLIB2,DISP=SHR
//STEP1     EXEC PGM=SAMPLE,PARM='8106'
//INFL      DD  DSN=TEST.DATA,
//            DCB=(BLKSIZE=1000,LRECL=100,RECFM=FB),
//            VOL=SER=DTF005,UNIT=3350,
//            DISP=SHR
//PRINT     DD  SYSOUT=A
//SYSOUT    DD  SYSOUT=A
//SYSUDUMP  DD  SYSOUT=A

TSOでのテスト

FREE F(INFL,PRINT,SYSOUT)
ALLOC F(INFL) DA('TEST.DATA') VOL(DTF005) -
       UNIT(3350) SHR
ALLOC F(PRINT) -DA(*)
ALLOC F(SYSOUT) -DA(*)
TEST 'TESTLIB2(SAMPLE)' '8106'

TSOでテストする時は、まずファイルの割り当てが必要。JCLではJOBLIBにモジュールを指定するが、TSOではTESTコマンドで直接指定する。パラメータは単引用符で囲んで指定する。
